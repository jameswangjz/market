# API / 模型 API 自动交付 Worker

## 本批范围

继续 TRD-BE-012、TRD-QA-003 和 TRD-OPS-002：在已有文件、SaaS 自动交付之外接入 API / 模型 API 适配器。编码使用 gpt-6-luna medium；需求边界、独立审查及运行验证由当前主模型负责。本文件初始为设计记录，未执行的测试不能标记通过。

## 完成条件与安全边界

1. 仅处理新版快照、全额支付、无退款的有效线上订单；订单与交付任务加锁，使用既有 Worker 和重试调度。
2. 产品不得安全下架；版本必须属于该产品。既有版本接入证据、SSRF 安全健康检查、APISIX 实际路由配置均须一致。
3. 只有上述验证成功，才在同一数据库事务登记该订单的订阅期限、完成履约；失败不遗留数据库订阅权益。重复处理不得重复增加期限。
4. 已存在的企业共享凭据沿用原密钥，验证实际 APISIX Consumer 和 Redis 订阅策略；不清零计数、不自动恢复主动停用的凭据。同版续费追加未来权益段，不叠加当前额度。
5. 首购尚无调用凭据时，平台登记访问权益，买方仍通过订单内现有凭据管理入口安全生成共享 API Key。后台不创建无法交付给买方的一次性密钥；本批不声称已实现支付后自动下发可下载的 KeySecret。
6. 外部错误不得包含 OAuth Secret、API Key 或第三方返回正文。失败按既有三次尝试、10 秒间隔处理，耗尽后转人工；SQL 事务异常交由 Worker 回滚。

## 事务与外部一致性

APISIX / Redis 与 PostgreSQL 不构成分布式原子事务。完成前先检查外部路由和消费者；同步失败时必须回滚数据库权益并恢复或保守拒绝缓存授权，不能使数据库交付失败而数据面已放行新权益。并发续费以组合锁串行；后台租约、支付幂等和既有状态机仍有效。无法保证外部补偿时保留异常与人工处理，不以静默成功掩盖。

## 验证矩阵

- API、模型 API 首购成功，自动完成且无需购买方验收。
- 健康检查失败、路由被改动、Consumer 密钥不匹配、策略缓存同步失败均不得完成。
- 同版续费连续接期，共享凭据稳定、用量不清零，主动停用凭据不复活。
- 重复处理无重复期限、日志和消息；失败重试三次后异常，人工重试保留审计。
- Worker 能发现两类订单；非买方、普通成员不能获取凭据。
- 独立 PostgreSQL / APISIX / Redis / 模拟上游测试只操作随机隔离夹具；精确清理对象，保留 ORD-261012005144E1B3 及其产品。

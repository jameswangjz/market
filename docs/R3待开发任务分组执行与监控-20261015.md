## 分层测试

1. 小改动仅运行受影响模块的定向测试，包括相应正常、权限、幂等、错误及回滚边界。
2. 同组前后端契约齐备后，执行一次组内集成验证；发现缺陷后只复测受影响项和必要邻接模块。
3. 跨组功能稳定后集中执行组合回归。不因单个按钮或字段修改重复商城、支付、SSO、清算全量流程。
4. 本地隔离测试、已部署接口测试、真实浏览器测试分别记录，不互相替代或冒称。

## 监控规则

- 仅实际开始的任务转进行中；等待依赖的任务保持待开发并注明依赖。
- 每个Agent同一时间一个有界任务包；主Agent管理契约、代码边界及测试证据。
- 以实际代码变化、测试日志和进程输出判断活动；等待外部请求或测试超预算时先查进程与连接，不盲目重启。
- 持续执行期间每15分钟核对任务活动；超过30分钟无有效活动记录原因，定位卡顿后缩小测试、取消重复运行或重启有界任务。时间流逝不产生进度。
- 状态更新需有实际步骤/测试证据；review要求相应部署或验证证据齐全，done仅由用户验收。
- 需要用户确认时独立提问；其他无关任务可继续。历史业务数据迁移必须先获得对应批准。
- 此处指本次持续执行时的管理，不宣称Agent在对话停止后仍有后台编码进程。

# 产品交易履约运行集成验证

## 已完成范围

- TRD-BE-003：版本独立网关配置、审核后接入验证、原生 APISIX 发布、健康检查及上游地址安全校验。
- TRD-BE-006：线下订单提供方审核、报价和成本调整、付款前冻结及审计。
- TRD-BE-007：买方企业超级管理员发起支付，平台超级管理员和财务人员确认到账；重复确认不重复生成交付任务。
- TRD-FE-008：按角色显示支付、到账确认操作，保留模拟支付方式。
- TRD-FE-007：本阶段完成提供方审核弹框；完整开工、验收、整改和附件操作仍待后续验证，不将整个任务提前标记完成。

## 验证证据

1. 本地后端回归 239 项通过；前端测试 42 项通过，生产构建通过。
2. 开发 Kubernetes 环境中使用真实 PostgreSQL、MinIO、ClamAV 和 APISIX 验证两个版本的独立路由、限流参数、无凭据拒绝、有效凭据调用和超频拒绝。
3. 接入验证在运营审核完成前拒绝执行；运营审核通过后自动验证、发布，仅已验证版本可购买。订单按购买版本选择路由。
4. 实际数据库验证提供方调整报价、买方无成本信息、买方管理员不能支付、财务确认支付及重复确认幂等。
5. 两个并发提供方审核请求得到 200/409，仅一条审核审计记录，订单与支付单报价一致。
6. 浏览器验证提供方审核弹框在桌面及 390 像素移动视口正常显示；拒绝原因和价格低于成本校验生效。
7. 临时测试产品、用户、订单、消息、网关路由、凭据及对象存储内容清理，不修改用户现有测试产品。

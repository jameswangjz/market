# BE-011跨版本退款事务接线与验证

文档编号：01。生成时间：2026-10-15 18:33:03，北京时间（UTC+8）。

## 已接入的功能

1. 可信API版本切换采用原子Redis回执；核对目标策略读回、来源epoch及订单/期限归属后，在同一数据库事务保存回执。版本修订与目标账本验证后生成不可变经济段；事务回滚、幂等重放、哈希与外键均有校验。旧版无可信回执的计划不补造历史。
2. API实际扣额按Stream水位数值划分新旧经济段，而不是按请求预取时间切分。逐月核对水位前基线、数据库追平及Redis计数；过期窗口也不能丢掉原月份。当前和未来续费订单分别计算本段用量与剩余额度。
3. 同一企业、产品、订阅组合及代次内的原支付和已完成升级补款构成资金来源池。申请时按最近支付优先预留，审批时复核原分配、经济段及哈希并冻结；每笔支付不得超过实付减已退及在途占用。资金腿与收入/成本/分账经济腿独立。
4. 拒绝通过状态释放预留，不删除不可变分配证据。审计及通知发件箱失败时整笔事务回滚。普通退款与版本变更互斥，降级和补偿也尊重同一支付来源的占用，避免兼容payment_id与实际多资金分配重复计算。

## 验证边界

PG案例使用真实主应用模型、不可变窗口校验、资金来源图及ASGI处理器；外部Redis回执/计数为明确的模拟源。独立Redis/Lua验证不能冒充完整APISIX网络链验证。真实银行、实际资源回收执行、完整浏览器退款交易均不在本轮范围。

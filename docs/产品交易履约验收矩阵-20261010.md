## 3. 已冻结默认与兼容边界

本表是本轮直接采用的实施和验收基线，不是待用户重确认事项。落地缺失标为实现依赖，不重新打开业务决策。

| 默认 | 已冻结规则 |
| --- | --- |
| D01 周期与时区 | 日期时间存UTC；业务订阅与财务自然月均以Asia/Shanghai计算边界，再转换UTC查询。交付成功起算，月付1..36月，周期半开 `[start,end)`；月quota按订阅月、日quota按北京时间，0不限且千次转整数，分钟限流保留。财务仍按付款/退款/经济调整完成事件的北京时间所属自然月，不由服务周期替代。 |
| D02 原始对应日 | 已冻结：锚点严格保留原始购买/交付日期day，不使用sticky monthend。1/31 -> 2/28 -> 3/31；1/30 -> 2/28 -> 3/30；原始2/28固定day=28，下一月为3/28，绝不因2/28是月底变成3/31。只有目标月无对应日才取该月末，下一月恢复原day；初始或截断日期是月底均不改变day，无需再次确认。 |
| D03 续费与过期恢复 | 有效组合接期续费；同版续费不增加当前period限额、不清零用量，未来段不生效。单纯到期且原租户仍存在时，恢复服务并在交付成功后起算新段，历史锚点/期限不覆盖。只有已关闭租户适用既有至少1个月数据保留和recover_until边界；超出恢复保障须核验第三方是否仍保留，不承诺可恢复，也不隐式新建租户。 |
| D04 切片金额与舍入 | 经济切片按来源订单的完整购买时段计算剩余秒比例，旧订单实际总价成本与目标月价成本乘原月数后比较；当前合同与未来已支付续费合同分别处理。QuotaPeriod只定义每月预算，不将各月平均金额另作分母代替用户的原订单比例公式。CNY、Decimal精确到分，五方尾差归provider；原规则冲回/目标规则计入。新版版本售价不得低于成本；合法版本之间成本差造成净调整利润负数时按signed记录，不截零。零差价仍记录成本与双腿清算；连续变更按当前有效经济基线冲回，不重复冲回最初订单。 |
| D05 收款与买方确认 | 订阅/验收为当前选定认证买方企业active super/admin，支付发起仅买方super；保留仅财务到账确认，平台普通super/operator不得通过平台身份冒充买方支付，也不扩展为财务确认例外。普通成员仅授权SaaS访问，不获文件/API权限；各动作独立鉴权，不用单一admin helper。 |
| D06 独立经济来源 | 双腿经济调整使用独立source ID及快照，原paid订单不净额改写；负向原规则、正向目标规则。关联净支付不再次全额正清算，关联净退款不再次触发通用refund负清算；普通未关联调整的完成退款仍按Refund唯一来源生成负单。资金退款状态与经济变化分离，重试不能双冲。 |

| D08 首期兼容与迁移 | 首期不新增legacy永久购买，不将既有永久实例/订单强转成月付，也不自动重算历史期限。新字段additive，旧paid订单、成本、paid_at与来源不覆盖；缺证据标unknown。旧APISIX计数仅按有证据的来源映射守恒迁移，无法确定的历史重叠标数据核对依赖，不以猜测扩大授权。 |

### 3.1 可复算财务 oracle

独立分支 fixture：三个已支付的独立单月来源合同各收入100/成本40，总 paid=300、成本120；第一份合同已使用，未来两份合同均未开始。此处每slice为独立来源订单，不是把一个三月订单按月平均拆分；单个三月来源订单的部分变更须另外按其完整时长秒数比例测试。

1. 升级目标每slice收入160/成本70：按旧规则冲回未用收入-200/成本-80，按目标规则重新计入收入+320/成本+140；净收入+120/净成本+60/净利润+60。原订单仍300/120，累计经济收入420/成本180/利润240。不能仅按一种分成规则对净差额分账。
2. 降级目标每slice收入70/成本30：旧规则冲回-200/-80，目标规则计入+140/+60；净收入-60/净成本-20/净利润-40。原订单仍300/120，累计240/100/140。此时-60是合同减价/credit，尚不能宣称退款完成。
3. 不可同时把订单净额改为420/240，再叠加差额事件；每个业务事件只能计一次。成本与收入分开保留符号，`profit=income-cost`，五方明细之和与允许分配的利润一致。
4. 部分退款须分配到实际剩余可退款的slice/事件余额，扣除已记减价/退款；不能对全额300再次冲回已取消的future slice。双腿调整关联的净退款只履行资金退款，不再生成通用refund负清算；未关联调整的普通退款维持独立负单路径。
5. CNY使用Decimal最小货币单位；切片尾差确定性归入末个适用slice，五方分成尾差归provider，所有总额守恒。100次小额退款累计不得超本金/原成本可冲回额度；合法版本成本差形成的signed负调整利润完整保留。

6. Playwright 使用买方 super、buyer enterprise_admin、普通成员、另企业 super、provider、finance、platform super/operator、停用账号及匿名 browser context。HTTP/HAR/assertion 为主，截图辅助；敏感 trace/token先脱敏。

## 6. 执行证据与禁止假报

- 每case产物：契约版本、应用/网关revision、fixture manifest、角色、HTTP请求ID/状态/脱敏响应、PG只读assertions、Redis精确key/TTL/counter、mock provider/SSO日志、Playwright断言与桌面/移动截图。
- 财务oracle独立于生产计算helper；校验原快照、差额事件、refund事件、参与方明细、批次和报表六层，不能仅比较HTTP200。
- 用例状态仅 `planned / blocked / failed / passed`；执行前置缺失、真实依赖不存在、SSO仅mock machine token、只有SQLite或截图均不能标passed。失败精确反馈函数/HTTP、输入、实际与预期，由主agent修复。
- 迁移单独验证旧schema->新schema及重复运行，检查列默认值、索引/约束、历史行摘要；create_all新表通过不代表additive migration通过。
- cleanup使用测试manifest逐个撤销自建consumer/route、删除精确Redis对象、drop测试schema与测试文件；禁止删除历史实例、共享key或生产schema。清理失败作为残留报告，不隐去。

## 7. 真实资金与四账限制

目前没有外部银行、支付网关真实交易、真实清算通道、到账回执及退回资金条件。本计划最多证明真实PG/Redis/APISIX与mock外部服务下的平台内部一致性。

`Payment.status=paid`、`SIM-PAY-*`、provider mock成功、人工财务confirm和平台Refund.completed都不等于真实入账/出账。未来接外部通道须另验签回调、重复/乱序回调、金额币种一致、银行流水唯一归属、部分到账/退款、手续费税项、清分回执、差异处理和对账关闭。未提供这些证据前，外部real funds及真实四账验收一律blocked，不做真实付款/退款演练。

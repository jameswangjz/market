# 控制台体验与SLA矩阵详细设计

编号：31；对应需求30；北京时间2026-10-16 15:50:59。

## 1. 分层与兼容

前端复用MainListFilters、PaginationControls及现有Tab样式；SLA拆为四个工作区，原证据组件中的企业记录移至绑定区。接口由后端统一执行可见范围、筛选、稳定排序、计数和分页。分页参数保持可选，不强迫既有下拉和后台消费者一次性迁移。

## 2. 矩阵存储与接口边界

按服务级别保存不可变矩阵修订：级别ID、版本号、来源级别、完整指标JSON、固定日历JSON、创建人和时间。当前版本引用与新增修订在同一事务提交，更新携带预期版本以避免覆盖；冲突返回409。初始版本从当前已确认矩阵构建，迁移不得覆盖人工配置或修改已有快照。

读取返回完整矩阵及可编辑字段清单；修改只接收已知指标的target/warning，不接受直接覆盖任意JSON。验证数值有限性、单位范围和预警方向；派生秒数由服务端计算。自定义级别从指定内置级别当前完整矩阵复制；后续父级修改不自动传播。

冻结函数读取当前矩阵修订，复制完整规则及日历、计算内容摘要，并保留原服务级别/企业绑定来源。在线考核、工单时钟均消费冻结规则，历史profile仅用于只读历史说明，避免双写系统。

## 3. 绑定与到期

调整绑定锁定企业及当前绑定，关闭旧有效区间，新增绑定并记录原因和前后快照。当前级别根据有效区间计算，未绑定/已到期使用标准。到期审计使用唯一事件标识，定时扫描或已有后台执行器补记一次；新冻结即使扫描未运行也必须正确回退。列表返回当前值与来源，历史另行展示，不把历史100条当作企业全量现状。

## 4. 审计与列表

动作中文映射集中维护，未知动作保留可读回退及原代码，避免错误翻译业务含义。筛选CSS限定在列表容器，不全局放大label/input；分页固定控件尺寸并响应式分组。用户企业列表按现有授权函数构造基础查询后才计数，排序增加ID作为稳定次序。

## 5. 测试与发布

后端局部测试：矩阵校验/版本冲突/完整复制/旧快照/到期回退与幂等/列表权限与空页。前端局部测试：Tab归属、可编辑字段、中文动作、分页状态及布局约束。完成关联模块后统一浏览器回归，不为每个小修改重复全量交易测试。

部署前备份数据库和清单，发布API/Web同一Git来源，标签YYYYMMDDHHMMSS-GitSha；验证就绪与实际接口，再将有证据任务置待验收。失败保留原因及未覆盖项，不以代码编译成功代替部署验证。不得改动受保护订单ORD-261012005144E1B3及依赖产品。

### 已落地接口契约

- GET `/api/sla/matrices`：完整矩阵、修订版本及CSV固定字段的`display_metadata`，按内置顺序返回。
- GET `/api/sla/service-levels/{id}/matrix`及`/matrix/versions`：当前矩阵与不可变历史。
- PATCH `/api/sla/service-levels/{id}/matrix`：`expected_version`及`metrics.{key}.{target,warning}`；版本冲突409，非法值422；分钟目标要求正整数，预警允许小数。
- POST `/api/sla/service-levels`：`code/name/description/base_code`，内置来源完整复制；不允许同时覆盖固定权益。
- GET `/api/sla/enterprise-bindings`：`q/service_level_id/assigned_by/expires_after/expires_before/page/page_size`；日期需带时区。
- POST `/api/sla/service-level-assignments`：沿用绑定接口，原因必填，支持空到期时间。
- POST `/api/sla/expire-bindings`：管理人员补偿扫描；同时在现有五分钟SLA在线任务中自动扫描，GET不产生恢复审计。
- GET `/api/users`：可选分页，以及关键词、激活状态、实名状态、平台角色、企业ID/企业名称筛选；GET `/api/admin/enterprises`：可选分页、名称/信用代码、认证状态及企业类型。

新增表`sla_matrix_versions`唯一约束为级别与版本组合；`sla_expiry_fallbacks`按绑定ID唯一记录审计回退。旧规则和旧级别元数据写接口返回410；历史读取继续保留。发布时同时更新API、Web和`sla-online-monitor`镜像，避免周期任务仍运行旧逻辑。

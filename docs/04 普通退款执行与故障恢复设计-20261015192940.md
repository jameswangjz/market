# 普通退款执行与故障恢复设计

文档编号：04。生成时间：2026-10-15 19:29:40，北京时间（UTC+8）。

## 目标与范围

承接BE-011已冻结的经济方案及支付来源，开发BE-012普通退款执行，并补齐FE-008执行/重试入口和QA-005故障验证。支付采用模拟确认，不调用银行，不将模拟结果描述为真实原路到账。版本降级退款仍走既有受控版本变更流程，不能由普通退款接口绕过。

## 权限与入口

- POST /api/refunds/{id}/execute：平台系统管理员、平台运营人员执行已批准的普通退款。
- POST /api/refunds/{id}/retry：相同角色恢复失败执行，不重新申请资金或重复退款。
- 请求包含expected_version、idempotency_key、reason；原因必填。财务、交付监控、买卖方企业管理员不能执行或重试。
- 以服务端allowed_actions和execution_available控制按钮，前端不自行根据paid金额推断可执行。历史、版本变更、缺证或资源无法安全回收的对象拒绝自动执行。
- 响应仅返回安全进度、执行模式和受控错误，不返回成本、提供方凭据、Token或原始网关配置。

## 持久执行流程

批准后的冻结方案校验 → 登记执行意图 → 资源回收并验证 → 逐支付来源模拟确认 → 完成普通退款。

每个阶段持久保存标识、方案指纹、执行次数及结果。使用短数据库事务、订单/订阅组合/支付锁和版本门禁；外部调用不跨长数据库事务。重启后继续未完成阶段，不能仅在内存保存执行状态。

执行前重新验证冻结方案哈希、审批版本、经济段及资源归属、退款余额和实际扣额。不能执行已失效报价或静默修改批准金额。每个资金腿绑定退款及原支付，累计不超过该来源实付减已退及其他在途占用。已成功资金腿不可重做。

不引入未经确认的“审批5分钟后永久失效”规则。审批时间与当前时间不同不等于方案失效；执行时重新核对可退余额、冻结经济基数及回收量，并在资源写入时处理并发变化。GET列表/详情仅展示资格和已持久进度，不获取写锁、重新预留资金或修改资源。

## 权益回收

有限额度API依据冻结经济段按退款比例扣减额度；优先收回尚未使用额度，保留实际已用量和企业共享凭据，不修改其他订单权益。剩余有限额度为零必须拒绝调用，不能写成0后被当作不限额度。

不限额度API和SaaS按冻结比例缩短尾部期限，保留原始经济分母与日历锚点，不重置用量。SaaS由第三方明确接受缩期请求并经STATUS读回验证；只有更新平台数据库或发出请求但没有验证，不算资源回收成功。

用户补充确认：不限额度API的网关到期精度为整秒，精确截止时刻向上取整，最多额外保留不足1秒访问；不得超出原网关已授权期限。退款金额、经济段及财务记录不舍入。持久资源计划保留精确截止、网关截止及舍入规则供审计。SaaS继续使用微秒精确截止，不采用该网关舍入。

部分退款后的权益必须以可信持久回收记录重建，不能因订单出现refunded_amount就整单丢弃，也不能后续同步旧策略时复活已退额度。多续费段若出现中间空窗，不能只改整体到期日期并假称已回收；第三方必须能表达相应区间，或明确拒绝该场景。

实际网关扣额与退款回收必须在原子门禁下处理，不能让核验和资源写入之间的并发调用突破退款上限。缺少可靠资源快照或不支持缩期协议的应用保持受控不可执行，不伪造成功。

## 故障与补偿

资源失败时不得标记资金已退；资源成功而资金失败时保留可恢复限制及资金预留。资金已经成功后不得撤销成功事实或恢复已退权益，以幂等续跑修复剩余步骤。

外部成功、本地提交失败时，通过持久幂等键及外部读回识别已有结果。状态、执行事件、审计与通知Outbox在本地事务内一致保存；事务失败不产生成功事件。完成记录为后续BE-013负向清算提供唯一退款关联证据，本任务不假称月度清算接入已完成。

## 验证分组

1. 状态与权限：执行、重试、重复点击、过期版本、越权、跨企业和受控来源拒绝。
2. 金额与资金：单来源、多来源、最近补款优先、部分退款、累计超退及并发竞争。
3. 资源：有限额度耗尽、并发扣额、期限缩短、无关订单隔离、SaaS缩期读回及失败拒绝。
4. 故障恢复：资源失败、资源成功提交失败、资金腿中断、完成审计/Outbox失败、进程重启。
5. 集成：一轮受影响组合及隔离PG验证；部署后验证真实HTTP权限、模拟资源及前端执行入口。禁止为单个小改动重复全平台测试。

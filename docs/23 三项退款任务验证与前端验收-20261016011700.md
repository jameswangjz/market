## 2. 本轮实现

1. 文件自动退款具有独立、持久化、幂等的资源回收回执，不伪造订阅周期。先回收资源，再执行模拟资金退款；资金失败保留资源回收结果，重试不重复扣减或恢复权限。
2. 文件部分退款沿用用户确认规则：停止该订单后续下载，不删除产品原文件，不影响其他订单。下载授权与退款回收采用同一订单锁，避免并发绕过。
3. 文件退款计划冻结成本、清算规则、历史已完成退款集合。连续部分退款延迟生成负向清算时，成本按累计差额冲回，历史回执不因后续退款改变。
4. 修复 SaaS 续费先后判断：先退后续续费订单，再退较早订单；较早时段不再错误阻塞最新续费退款。

## 4. 边界与清理

- SaaS 组使用真实部署的 OAuth 和模拟 SaaS HTTP，不是真实第三方生产 SaaS，也不是完整浏览器交易。
- 文件组存储读取采用精确替身，扫描元数据为测试夹具；不代表本轮重新完成 MinIO 网络、上传、病毒或 Presidio 扫描测试。
- 跨月组调用生产业务处理程序，但供应商 CHANGE/STATUS/RENEW 使用内存模拟；资金均为平台模拟支付，不涉及真实银行。
- 原生网关首轮业务断言通过但清理遇到并发 SLA 子记录，证据 33 保留失败结果，34 记录按拥有权补充清理；独立最终完整重跑 35 通过，未将首轮失败冒称通过。
- 隔离数据库结构及临时认证根已移除；SaaS 临时租户关闭但保留，未声称物理删除。网关测试保留不可变 SLA 事实，不清空公共流、游标或其他任务数据。
- 受保护订单 `ORD-261012005144E1B3` 和依赖产品保留。实际链路组检查前后指纹；隔离 PostgreSQL 组仅做存在数量检查且没有公共业务写操作。

## 5. 前端验收建议

请使用新建的自有测试订单，不操作受保护订单。

1. 买方企业超级管理员或管理员进入订单/售后退款入口发起请求；平台管理员或运营人员审核。文件如需人工核定，填写核定依据后再执行。
2. 文件订单执行退款后，原订单下载应不可用，另一个有效订单仍可下载；查看退款执行记录、资源回执和操作审计。失败案例重试后不应出现两次资金退款。
3. SaaS 组合先退最新续费，核对到期时间缩短；仍有未退款后续续费时，较早订单应被阻止，且不能提前产生资金退款。
4. 清算分账中核对退款完成月份的负向清算单、订单关联、成本冲回及五方金额，在线报表与导出一致；已确认/已付款批次不能随意重建。
5. 浏览器页面实际展示及用户操作请据此验收。本轮没有声称新增完整浏览器自动化覆盖，待验收不等于用户已确认通过。

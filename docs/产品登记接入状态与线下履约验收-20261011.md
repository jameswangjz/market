# 产品登记接入状态与线下履约验收

## 本批范围

推进 TRD-FE-004、TRD-FE-005、TRD-QA-004。沿用现有交易快照、版本网关、审核和企业权限，不以新界面绕过四阶段审核或已售版本冻结。

## 登记与版本配置

- 交付方式按线上、线下分组；产品 Logo 必填，尺寸仍由后端校验为 380×280。
- 每个版本独立录入价格、成本、简要介绍。API、模型 API、SaaS 使用元/月，文件及线下服务使用元/单。报价不得低于成本。
- 文件交付按版本选择压缩包；保存后按返回的版本号绑定版本 ID 上传，支持 zip、tar、rar、7z 等既有格式。
- 每个 API/模型 API 版本独立配置上游 URL、路由标识、入口 API Key 认证、上游 OAuth2/无认证、Scope、超时、健康检查路径/GET/HEAD及路径前缀处理。
- 月配额以千次输入、以整数调用次数保存，1 表示 1000 次、0 不限；每日配额 0 不限，保留每分钟限流。
- JSON 登记请求仅包含白名单产品和版本字段；文件和接入配置通过各自接口保存，不夹带密钥、健康结果、审核日志。
- 保存附件失败保留已创建草稿和待上传附件；重试更新同一产品，不重新创建产品。已成功上传的版本文件不重复上传。

已售版本仍由后端拒绝覆盖。当前接口未提供逐版本已售标志，前端尚不能自动禁用所有已售字段；兼容性元数据、SaaS OIDC 回调配置也尚无后端契约。本批不伪造这些字段，TRD-FE-004 保留进行中。

## 接入状态

API/模型 API 产品详情新增“版本接入状态”区域，显示各保存版本的配置状态、路由标识、健康检查方法/路径、HTTP 状态和最近验证时间。

使用现有接口：

| 操作 | 接口 |
| --- | --- |
| 查询证据 | GET /api/products/{product_id}/versions/{version_id}/integration |
| 接入验证 | POST /api/products/{product_id}/versions/{version_id}/integration/verify |
| 提供方凭据下载 | GET /api/products/{product_id}/oauth-credentials-download |

只允许待接入验证或已发布产品执行接入验证。按钮执行现有健康检查和网关发布流程，成功后刷新实际证据及产品状态；失败不假装发布成功。请求失效或切换产品时不显示旧产品返回的数据。

提供方规范可直接下载。修复审核后 pending_integration 状态不能下载 OAuth 凭据的问题；提供方管理员依据实际产品所属企业的成员关系授权，不按默认企业推断。平台角色即使存在遗留企业成员关系也不能下载提供方 Secret，普通成员和未实名管理员不能下载。下载响应为附件并设置 no-store/no-cache，不在状态区域显示 Secret。

SaaS 开通验证和 OIDC SSO 尚待 TRD-BE-013/014/015，不将 API 接入状态实现等同于全部线上交付已完成。

## 线下履约验收

真实 PostgreSQL、MinIO、ClamAV 环境分别运行 training、consulting、custom：

1. 创建订单进入待提供方审核，未审核不能支付。
2. 提供方超级管理员或管理员审核；拒绝必须填写原因并终止订单。非法角色、低于成本报价、缺少改价原因不产生副作用。
3. 审核金额和成本冻结入订单快照；买方详情不含成本或内部审核成本说明。
4. 超级管理员模拟支付确认后进入待开始履约；企业管理员不能发起支付。重复确认不重复生成履约任务。
5. 提供方开始履约、提交交付，买方拒绝后进入整改；提供方重新提交，买方确认完成。
6. 上传真实附件并验证病毒扫描；EICAR 标准无害病毒测试串被拒绝；验收中和终态不能替换交付材料。
7. 校验任务、状态日志、操作人员、原因和审计数据；目录修改不改变订单快照。
8. 使用外层事务回滚并清理本次精确归属的 MinIO 前缀，验证数据库无测试行残留。

另有两个隔离数据库测试，分别对三种交付注入报价/支付通知失败，验证金额、成本、快照、支付、日志和审计回滚，重试成功且仅保留一个履约任务。

真实服务脚本为顺序调用；隔离数据库回滚测试不等同于 PostgreSQL 并发实测。并发支付确认、并发报价与支付相交的证据仍待补充，TRD-QA-004 保留进行中。真实外部支付渠道仍未接入。

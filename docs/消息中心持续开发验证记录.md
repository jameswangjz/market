## PostgreSQL 隔离验证脚本

脚本：`scripts/message_center_pg_verify.py`。读取 Pod 的 DATABASE_URL，但不导入 main、不读取业务表、不发邮件。生成随机 `mc_verify_<hex>` schema，SQLAlchemy metadata 全部显式限定 schema；每次连接 checkout 核验 current_schema/search_path；连接无 public 回退。测试完成或失败时 finally 删除 schema，并查询系统目录确认删除。

PostgreSQL TEMP TABLE 只能在创建它的连接中访问，无法用于四个连接/两个 worker 的共享并发验证。因此使用临时生命周期的独立 schema 表，所有测试数据仅存在该 schema；不改变生产表或数据。进程 SIGTERM/SIGINT 会进入清理；SIGKILL/Pod 强制销毁无法运行 finally，需按输出的随机 schema 名检查残留。

验证内容：

- 四个独立 Session 同 event_key 返回同一 message id，计数 Message=1、Receipt=1、Outbox=2；Outbox 两条分别是 realtime/email，即每通道仅一条。
- 单独事务锁住最早待处理任务，process_once 必须跳过并完成其他任务，证明实际 PostgreSQL SKIP LOCKED 生效。
- 两 worker 同时领取不同 realtime 任务，在 mock 外部 I/O 阻塞时核验两条 processing 记录、不同 lease token、attempts=1 和匹配 DeliveryAttempt；释放后两条各完成一次，无重复投递。

部署后将脚本复制到新 Pod 的 `/tmp` 再运行，不修改运行 /app：

```bash

kubectl -n market exec "$API_POD" -- python /tmp/message_center_pg_verify.py --module /app/app/message_center.py
```

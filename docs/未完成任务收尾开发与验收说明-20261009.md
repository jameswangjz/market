# 未完成任务收尾开发与验收说明

## 1. 范围和基线

本轮针对BE-022、BE-028、BE-029、FE-013、QA-006、QA-007、QA-010、ARC-006和BE-024。
执行原则：可以在当前环境实现和验证的部分继续完成；缺少真实支付、银行和分账回执的部分明确延期，不用模拟结果冒充真实资金验证。

按后续确认的最新清算口径执行：以指定月份内支付确认的订单及完成退款的负向清算调整单生成清算批次；售后状态不阻断清算；利润按订单版本成本计算；调整采用提案、对方决定、确认锁定机制。

## 2. 功能实现

### 2.1 计量追踪（BE-022）

- 人工计量由有权限的平台人员、订单相关企业管理员登记，校验订单归属、类型、数量、单位和时间区间。
- 人工登记状态为待核验，不因为登记成功直接声明已校验。订单、来源和事件键形成幂等身份；不同内容不能复用同一个事件键。
- 支付、退款、交付及下载事件关联真实业务记录，在同一事务内落库，业务失败回滚时计量和通知一起回滚。
- APISIX/Redis累计计数作为快照，不当成单次调用；缺失计数、计数回退和不可用标记待处理，不能推断为零用量。
- 企业共享API凭证的累计量必须标识为共享凭证维度，不能重复计为多笔订单各自的独占用量。
- 计量用于额度、履约和审计追踪，不另行按实际调用量计费，也不替代当前月度支付清算依据。

### 2.2 审计接口及界面（BE-028、BE-029、FE-013）

- 请求号通过X-Request-Id关联，非法请求号替换为平台生成值；输出订单号及内部关联ID。
- /api/audit-logs 支持分类、关键词、操作人、订单号或ID、批次、规则、风险和时间范围；非法时间返回422，空时间不导致错误。
- /api/audit-logs/export 与列表采用同一筛选逻辑，输出UTF-8 BOM CSV，保留字段引用及前后值；防止公式注入；超过10000条返回413，要求收窄过滤条件，不静默截断。
- /api/audit-logs/{event_id}/timeline 返回关联事件及分页。单订单事件不混入同批次其他订单；对象级事件按自身对象关联。
- 敏感时间线查看和导出都有审计；平台管理、运营、财务、安全角色按授权访问，普通企业用户不能读取平台审计数据。
- 前端补时间范围、导出、关联时间线分页、前后值对比和有权限的业务跳转。
- 补分类/时间、订单/时间、批次/时间及稳定分页索引。

### 2.3 独立账单支持（BE-024可实施部分）

接口均要求平台管理、运营或财务清算权限：

| 接口 | 用途 |
|---|---|
| POST /api/settlement-batches/{batch_id}/ledger-import | 导入独立JSON账单，来源simulation或manual_import |
| POST /api/settlement-batches/{batch_id}/ledger-imports/{import_id}/compare | 逐订单比较，报告缺失、多余、重复流水及金额差异 |
| GET /api/settlement-batches/{batch_id}/ledger-reports | 查询持久化报告及处理说明 |
| POST /api/settlement-batches/{batch_id}/ledger-reports/{report_id}/resolve | 填写处理原因和依据后结案；不把差异改称已匹配 |
| GET /api/settlement-batches/{batch_id}/ledger-reports/{report_id}/download | 授权下载JSON报告，同时记录下载审计 |

导入字段：ledger_type（platform/payment/bank/distribution）、source_kind、source_name、event_key、entries。每行包含entry_no、order_no、amount和currency。金额精确到分，当前仅支持CNY，单次最多5000行，负数表示退款/负向调整。同事件键同内容复用，不同内容拒绝。

金额口径：platform/payment/bank代表订单收款净额；distribution代表五方利润分配金额。银行入款账与分账出款账不能混成一种比较口径。完成退款作为负向行参与对应月份比较。

重复流水不重复累加，但报告仍标记差异。漏单和多单即使总金额碰巧相等也不能判定匹配。
报告固定返回real_channel_verified=false；源数据必须来自独立输入，不能自动复制平台结果作为外部账单。
新接口用于可实施的对账支持和技术验收，不改变清算批次状态，也不触发真实资金支付。

前端入口：清算分账 > 对账差异 > 独立账单比对。选择批次和账簿，导入JSON后可查看逐订单差异、记录处理依据和下载报告。支持平台管理员、平台运营人员及财务清算人员；页面明确标注“未接真实渠道”。账单文件不超过5MB、5000行。

## 3. 本轮回归修复

- 旧产品publish入口拒绝直接发布，必须通过四阶段审核。
- 存在待处理清算调整提案时，不能锁定清算单、确认批次或付款。
- 旧按订单生成入口不能覆盖已付款、已锁定或已关联有效批次的清算单。
- 显式指定订单也必须满足支付时间区间；不绕过指定月份筛选。
- 清算批次幂等键与请求摘要绑定，不同周期、规则或订单范围不能复用；重复请求不重复分账。
- 批次生成使用PG事务锁，并移除100条订单的静默截断。

## 4. 暂不能完成部分及规避办法

BE-024及QA-006的真实资金验证尚缺：支付机构账单/API、银行入款及出款流水、实际分账回执、商户/收款账户、认证凭据及测试环境；到账延迟、手续费和账期等映射规则也需要外部资料明确。

本轮先完成独立模拟数据及人工导入的正常、漏单、多单、重复、金额差异、负向退款、权限和处理依据验证。正式数据源到位后保留相同标准账单结构，用适配器接入真实来源，再执行真实联调。不会新增未确认的自动支付或人工金额比较即算真实四账通过的逻辑。

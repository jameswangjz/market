# 清算收尾开发、部署验证与验收入口

生成时间：2026-10-18 19:20:19，北京时间。本文承接41—45号文档，记录本轮实际交付及剩余范围，不代表全部17项任务已经完成或用户已经验收。

## 1 本轮实现

### 1.1 跨版本最终基线

- 新增不可变经济段与最终清算基线关联，核验订单、版本、资源生效回执、冻结规则、摘要及提供方身份。
- 原版本剩余部分按最终确认成本及分成冲回；目标版本按自身最终确认值记入。原订单、版本变更资金及资源执行证明不被改写。
- 当前订阅及未来续费分别核算段差额，同时核验整笔净补款或净退款，不把整笔补款重复记入每个经济段。
- 目标单先锁定而原版本冲回尚未具备时，明确暂挂资金基线；精确原版本冲回完成后，补齐已锁定目标单的受控捕获。
- 后续退款使用精确目标段最终基线，累计分币计算；不按订单任意选取一张正向清算单。

边界：本轮自动财务评估支持一次退款对应一个具有可信证据的经济段。单次退款合并多个经济段、证据歧义或缺失仍明确暂挂；暂挂不阻塞已有获批买方退款的完成，不推定财务已结清。

### 1.2 不可返还成本金额应用

- 已批准成本例外不再仅存审批记录：冻结独立应用计划和摘要，记录保留成本、普通利润冲回、额外损失、承担主体及批准证据。
- 提供方成本、正常利润和额外损失分项记账；保留成本不会被偷偷计为提供方额外利润，也不会默认按原比例摊给其他各方。
- 示例：原收入150、成本100、利润50，退款30，默认冲成本20和利润10；批准保留成本5后，冲成本15、普通利润10，并由明确承担方承担损失5，合计仍为30。
- 全额退款时，损失可以超过承担方原利润分成，但作为独立责任记录，不冒充超过原基线的普通利润冲回。
- 累计退款、重复锁定及重试不重复应用成本例外；既有买方退款金额、资金证明、资源执行证明及退款上限不改变。
- 跨版本退款也可申请成本例外：从已完成退款的不可变证明定位唯一目标段，完成对方审批后刷新财务评估并锁定；错误根基线、重复负向单、超出对应退款成本、未完成或缺证退款均拒绝。
- 已产生财务冲回后，不允许再批准例外直接覆盖历史；需要显式后续调整。

成本例外、实际收益主体配置目前仍以已授权后端API为管理入口，完整管理页面与补差来源管理尚未全部完成。

### 1.3 其他收益主体报表

- 新增“我的收益”独立只读入口。服务方、专家、渠道的用户/企业通过真实收益主体绑定取得权限，不由配置该主体的提供方企业身份代替受益人身份。
- 本人收益与企业提供方全量清算权限分开；普通成员具有个人专家身份时，也可看到其本人收益，但不因此取得企业清算管理权。
- 仅展示本人归属的正常利润、独立承担损失、净应收、已付、未付、应追回、已追回、抵扣和待追回余额。
- 本主体净应收=本主体成本归属+普通利润分成−独立损失；其他主体成本、分成、买方订单身份、私有凭证依据不返回本人报表。
- 明细、月份、产品、提供方、主体汇总及CSV使用一致范围；不受当前页或2000条上限截断。年度快照和平台资金写入口不向本人收益角色开放。
- 本人报表不授予调整、锁定、付款、复核或其他企业查询权限；账号、企业或主体切换时清除旧结果并拒绝过期响应。
- 新增字段及相关审核动作已中文展示；选择框、检索、分页与页面风格保持一致，1440及390宽度实际浏览器检查通过。

### 1.4 资金执行与并发收尾

- 清算单捕获不在持有清算单锁时反向获取批次锁。
- 批次确认后执行精确原单未付抵扣；存在可抵扣应追回款时，付款不能绕过它直接支付毛额。
- 资金写操作与主批次确认/付款在获取批次锁前使用统一事务级互斥，避免交叉批次锁顺序相反。
- 增加实际主函数体及真实HTTP入口的PostgreSQL测试，而非只测试辅助函数；移除早期互斥锁的对照场景会被拒绝。

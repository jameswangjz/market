## 2. 完成本轮功能

1. 多来源退款逐经济段绑定最终确认基线、实际支付来源及累计退款水位，保留原订单、清算单、批次和证据哈希；混合来源不重复占用支付资金。
2. 外部补款退款额外冲回部分形成原补款方独立返还应付，支持准确来源抵扣及人工登记后独立复核，不作为第六方利润，不自动认定银行到账。
3. 逐段不可返还成本例外支持原始退款成本上限、证据及对侧整单审批；不改变买方实付、退款上限及原补款方返还金额。
4. 升降级时按最终清算基线冲回原版本未使用部分；外部补款形成原补款方返还权益，不转入新版本。平台内部吸收则恢复内部权益，不生成外部付款。
5. 新版本后续退款不再重复继承旧版本已冲回的补款。累计分币、来源预算、重试及并发均有校验。
6. 补款证据缺失时，新资金投影路径拒绝提前锁定并回滚，核验后可重试；旧版非补差waiting行为保持兼容。
7. 新增受权限约束的原始成本提案依据查询。前端使用未经例外调整的原始依据，支持普通单段、多段及补差单段、多段，不使用已应用例外后的值作为原始上限。
8. 前端返还付款独立成组，仅允许人工登记并独立复核；普通成本与利润合并付款保持兼容。内部恢复只能查看，不能登记外部付款。
9. 报表、下载、期间桥接及明细证据分别展示买方现金退款、财务冲回、外部返还及内部恢复；补款方仅能查看自身权益，不因此获得原订单完整成本。
10. 冻结来源、成本例外引用及版本资金投影均纳入重建保护，禁止通过重新生成批次破坏已使用的证据。

## 4. 前端验收入口

1. 清算分账 → 清算报表 → 明细：查看负向清算的实际退款、财务冲回、原补款方返还权益、来源及处理余额。
2. 清算分账 → 主体与成本 → 成本例外：选择已完成且尚未冻结入账的退款，逐段填写保留金额及证据，由对侧审批。已冻结、已入账或已有提案时应明确禁止重复申请。
3. 清算分账 → 应收应付：批次确认后选择返还应付行登记人工付款，再由另一名有权限的平台人员在资金凭证中复核。同一来源仍有可抵扣应追回款时，先按规则抵扣。
4. 清算明细 → 版本变更原补款投影证据：外部返还与平台内部恢复须清楚区分；内部恢复不得出现外部付款入口。
5. 开发进度控制台：两项任务均为待验收；用户完成前端验证后再确认完成。

示例仅作口径说明：买方实付150元、外部补10元、最终清算160元，买方退款30元，则财务冲回32元，额外2元为原补款方返还权益，不增加买方退款。升降级剩余50%时，原补款对应5元形成独立返还，不转入新版本。

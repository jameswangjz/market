# 清算管理与审计增强需求分析及开发计划

## 1. 编制依据与范围

本专项依据《数据集运营服务管理平台建设方案-20260929-订单状态重构-v5.docx》中的“1.1.1.1.1.4 清算管理功能要求”以及其中审计管理、订单、支付、交付、售后和计量计费的关联要求编制，范围包括：

- 清算触发、清算规则、规则版本和试算；
- 订单收入、退款、用量、交付验收、培训/咨询/定制里程碑等计量数据采集；
- 平台服务费、数据/服务提供方分成、数据服务方分成、专家费用、渠道费用和税费的计算；
- 清算批次、参与方确认、异议、付款、归档；
- 平台账、支付账、银行账、分账账四账对账和差异处理；
- 退款、冲正、补算、追回和后续批次抵扣；
- 面向清算全链路的结构化审计、分类快捷查询、关联检索和导出。

本文件是需求分析、开发任务拆解、验收和进度跟踪的依据。当前阶段不改变既有模拟支付定位，但需要把模拟支付流水作为清算和对账的可替换数据源。

## 2. 当前实现与主要差距

### 2.1 当前实现

当前平台已具备基础 `Settlement`、清算调整、清算锁定和 `AuditLog`，可以针对已支付订单按固定比例计算平台费、服务分成、专家费、税费和提供方分成，也会记录生成、调整、锁定动作。

### 2.2 需要补齐的能力

1. **清算触发不完整**：当前主要按订单生成，缺少订单完成、支付完成、交付验收、售后结清、授权期限和异常校验等资格判断，也缺少周期清算、里程碑清算和批次幂等。
2. **规则不可配置和追溯**：固定比例不能表达产品、服务类型、交付方式、计费周期、参与方、渠道、税费和退款规则；缺少规则版本、生效/失效时间、审批和历史订单沿用旧规则。
3. **缺少真实计量依据**：未统一沉淀下载、API/模型调用、授权期限、平台资源用量、培训出席、咨询工时和定制里程碑等计量数据，也没有对缺失、重复、异常数据进行拦截。
4. **分账模型过于简单**：未形成多参与方分账明细、参与主体资格/账户/合同/发票校验和风险冻结。
5. **对账和付款闭环缺失**：没有平台账、支付账、银行账、分账账四账对账，缺少差异单、确认/异议、付款流水、自动确认和归档。
6. **退款与冲正链路不完整**：调整会直接改变清算单累计金额，未形成与原订单、原支付、原清算批次关联的冲正/补算单，无法表达已分账后的追回、抵扣和税费重算。
7. **报表和审计不足**：清算列表字段有限，审计日志没有分类、筛选、分页、关联链、异常定位和导出，无法快速定位某个订单、批次、规则版本或差异。

## 3. 目标业务闭环

### 3.1 清算主流程

数据采集 -> 清算资格校验 -> 计量与计费 -> 规则匹配/试算 -> 生成清算批次 -> 多方分账 -> 对账 -> 参与方确认或异议 -> 财务付款/模拟付款 -> 归档。

清算资格至少校验：订单主状态完成、支付已完成、交付已验收、无未结售后/退款、计量数据完整、参与方账户和资质有效、合同/授权有效、规则已审批且在有效期内。任何异常均生成待处理事项，不得直接进入最终付款。

### 3.2 清算规则与试算

规则按产品/服务、版本、订单类型、交付方式、计费周期和参与角色配置，支持平台服务费、渠道费、提供方分成、数据服务方分成、专家费用、税费、退款追回和尾差处理。规则必须有版本号、适用范围、公式、参与方、优先级、生效/失效时间、审批人和变更原因。

规则正式启用前支持历史订单或指定订单试算，展示旧规则与新规则的金额差异；未审批规则只能试算，不能生成正式清算批次。历史清算必须保留当时命中的规则版本。

### 3.3 计量、分账和四账对账

计量数据保留来源系统、采集时间、结算周期、校验结果、订单/订阅/交付/接口调用关联。API、模型、下载和平台资源按实际用量计费；培训、咨询和定制开发按出席、工时、里程碑验收和交付物计费。

分账前校验收款主体、账户、资质、合同、发票/税务信息和风险冻结状态。对账至少覆盖平台业务账、支付流水账、银行/模拟银行账、分账账。差异形成差异单，记录差异类型、金额、责任部门、发现时间、处理期限、处理结果和关闭依据；差异关闭前不得支付对应款项。

### 3.4 确认、付款、退款和冲正

清算批次生成后，参与方可查看清算单和明细并确认或提出异议；到期无异议可按配置自动确认。已确认批次进入待付款，财务/平台运营人员记录付款时间、账户、金额、流水号和结果。

取消、部分/全额退款、重新交付、价格调整和售后补偿均创建独立的退款或清算调整单，关联原订单、支付流水、原清算批次和业务依据，不修改原始结果。已分账金额通过追回、未来批次抵扣或人工审批调整处理，并重算相关分成和税费。

## 4. 平台改造清单

### 4.1 后端与数据模型

- 新增清算规则、规则版本、规则审批、规则试算和试算差异模型；
- 扩展清算批次、清算单明细、参与方分账、周期、状态、确认/异议、付款和归档模型；
- 新增计量数据、计量校验、计费明细和来源关联模型；
- 新增四账账目、对账批次、差异单、差异处理记录和关闭依据模型；
- 新增退款/冲正/补算单，与原订单、支付、清算批次建立不可变关联；
- 清算金额使用 Decimal，计算过程保留输入、公式、舍入、尾差和输出；
- 清算操作使用批次幂等键和唯一约束，重试不能重复分账；
- 统一审计事件模型，增加事件分类、业务域、租户/企业、订单、产品、版本、支付、交付、售后、清算批次、规则版本、差异单、请求号、前后值摘要、结果和风险标记；
- 审计接口支持分类、关键词、时间范围、操作人、对象、订单、清算批次、规则版本、异常状态、分页、详情和导出，并按租户及平台角色做权限过滤。

### 4.2 前端清算管理

- 清算规则列表、版本编辑、审批、启停、试算和差异对比；
- 清算批次列表、资格校验结果、清算单明细、参与方分账、确认/异议、付款和归档；
- 计量数据校验、异常处理、四账对账、差异单分派/处理/关闭；
- 退款冲正、追回、未来批次抵扣和人工调整审批；
- 清算报表按周期、订单、产品、客户、提供方、数据服务方、平台、渠道、服务类型和状态筛选并导出。

### 4.3 审计日志界面改造

审计页面顶部增加可直接点击的分类按钮/快捷筛选，至少包括：

- 全部审计；
- 用户与权限；
- 产品与服务；
- 订单状态；
- 支付与退款；
- 交付与售后；
- 数据访问/API；
- **清算全链路**；
- 清算规则与试算；
- 计量计费；
- 分账与付款；
- 对账差异；
- 冲正与清算调整；
- 配置与安全；
- 运维与任务。

点击“清算全链路”后，默认只展示清算资格、规则匹配、试算、批次、计量、分账、对账、确认、付款、退款、冲正、调整和归档事件。页面提供订单号、清算批次号、结算单号、差异单号、规则版本、操作人、企业/租户、事件结果、异常标记、关键词和时间范围检索；支持清空条件、保存当前筛选、分页、查看事件详情、跳转关联订单/清算单/差异单和导出当前结果。

详情抽屉展示事件分类、动作、时间、操作人、来源 IP/请求号、业务关联、结果、失败原因、变更前后摘要、规则版本、批次号和关联事件时间线。审计事件不可修改和删除；导出和查看敏感详情本身也要写入审计日志。

## 6. 集成门禁

1. 后端模型迁移可重复执行，Decimal 计算和批次幂等测试通过；
2. 规则未经审批不能进入正式清算，历史清算可还原规则版本和计算依据；
3. 清算异常、对账差异、未完成售后和无效收款主体会阻止付款；
4. 原始清算和审计事件不可覆盖、删除，退款/冲正建立新记录并保留关联；
5. 审计快捷分类与后端分类一致，筛选结果可跳转业务详情，导出操作自身留痕；
6. 多租户、平台角色、企业管理员和财务/清算岗位权限测试通过；
7. 前端构建、后端接口测试、Kubernetes 部署和清算端到端验收全部通过后，专项任务才可标记 `DONE`。

# API提供方管理闭环需求、设计与任务

生成时间：2026-10-19 15:16:32（北京时间）。

## 1. 确认需求

移除API登记的产品级“提供方后端访问URL”选项，仅保留每版本业务上游URL；增加独立“API服务管理接口地址”。管理调用沿用平台统一OAuth2，提供方作为资源服务器，不新增第三方授权服务器或OIDC用户登录要求。

业务数据面由APISIX继续执行认证、期限和配额；管理面主动同步提供方企业/产品组合的开通、续费、版本切换、权益调整、关闭/恢复及实际状态回执。第三方获得一份完整提供方规范即可实现接口并联调，不依赖平台内部源码猜测字段。

## 2. 地址及历史兼容

- 版本上游URL只用于业务API、版本健康检查及网关转发。
- 管理地址使用产品现有integration_api_url持久化，必须独立输入完整URL，不从业务URL猜测或拼接。
- 保留数据库旧upstream_url字段以兼容已有记录，但不再作为新API产品配置必填；前端不再提交该字段，不因默认空串覆盖已售旧配置。
- 新产品提交审核必须有管理地址及各启用版本上游配置。旧订单按冻结快照处理：未登记管理端点的历史订单维持明确的unmanaged模式，不伪称已完成提供方同步，不自动改写旧快照。
- 已售配置保持原有不可覆盖保护，旧产品管理地址迁移须另行受控处理，不能为验收自动指向模拟程序。

## 3. OAuth与安全

业务调用使用resource.invoke，管理调用使用resource.manage，二者由同一平台OAuth授权服务器签发但权限隔离。审核为新管理产品配置机器Scope，已有客户端保留原ID/密钥/启停状态。接收方通过内省校验active、issuer、audience、product_id及操作Scope，再校验组合、企业及租户绑定。

所有管理URL遵守HTTP系统配置及SSRF校验，不跟随重定向；敏感Token不放入URL、回执或日志。管理协议不下发买方API Key、Secret、内部成本及清算比例。

## 4. 生命周期及对账

管理请求包含协议版本、事件ID、幂等键、产品、企业、订阅组合、分代、可选外部租户、订单ID/订单号、商品版本、本次月数及UTC起止日期；periods给出权威的订单时段和额度目标。平台决定截止日期，第三方不自行按收到次数累加期限。

首次交付先持久化预备操作及计划的组合/时段ID，不提前写入虚假的交付成功记录。随后执行并验证提供方，再完成网关和实际订阅记录。失败重试复用已提交的完整请求及日期。并发操作不得跨越尚未完成的冻结计划。

升降级及退款在已有Saga准备阶段冻结提供方计划，执行阶段必须验证提供方与网关资源证明；失败不能当作资金/清算成功。目标切换与补偿恢复使用不同固定事件键。退款只缩减受影响订单权益，保留无关订单；全组合关闭与单订单调整分开。

到期关闭只作用于购买企业的该产品组合；手工产品下架不自动关闭已售权益。提供方回执与STATUS读取实际保存状态，禁止仅回显请求宣称成功。Token的exp不代表订单截止日期。

## 5. 任务与验收

API-LC-ARC-001、FE-001、BE-001、BE-002、BE-003、QA-001、DOC-001、OPS-001已拆分，具体状态以开发进度控制台为准。先分别测试地址/权限、协议/模拟服务、交付、变更/退款，再统一组合回归；小变更不反复执行全量测试。

重点验证：协议两端字段一致；已提交计划重放；远程成功后平台回滚；同键异请求拒绝；错产品/企业/组合拒绝；日历与续费日期；升降级及退款未影响其他权益；管理Token不能替代业务Token；模拟状态重启不丢；规范实际下载文件一致。

本次不接入真实银行支付，不重置历史用量，不轮换真实客户端凭据，不删除受保护订单或其他业务数据。未执行的实际环境故障测试必须如实保留，不代用户完成验收。

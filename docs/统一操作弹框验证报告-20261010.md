# 统一操作弹框验证报告

## 实现范围

- 产品审核通过、审核拒绝采用共用 `ActionDialog`，与现有页面的字体、橙色顶边、遮罩、标题分隔线、输入框及操作区保持一致。
- 产品审核展示产品名称；拒绝原因不能为空或纯空白；审核通过默认填写“审核通过”，可编辑。
- 控制台原生 `window.prompt/window.confirm` 全部迁移至同一组件，包含撤回、下架、企业成员操作、清算操作、凭据重新生成等。
- 支持取消、关闭、Escape、初始焦点和键盘焦点范围；窄屏自动适配；排队处理多个弹框；组件销毁时取消待处理请求。
- 产品审核期间阻止重复弹框/请求；请求失败保留详情并允许重试。

## 验证结果

- 前端20项回归测试通过，其中7项覆盖弹框校验、取消、排队、卸载和审核提交保护。
- 开发服务器构建通过；镜像：`market-web:20261009130711-07d1e6d71d60`，符合UTC时间加GitSha标签格式。
- 实际Chrome验证：审核通过/拒绝样式、默认焦点、拒绝空内容校验、取消不发送审核请求、Escape取消、390px宽度下完整展示均通过。
- 浏览器测试只打开和取消现有待审核产品的弹框，未批准/拒绝产品，未改变用户测试数据。
- 验证脚本：`scripts/action_dialog_browser_cdp.ps1`；截图和结果：`docs/action-dialog-browser/`。
- 非审核原生弹框完成统一迁移及编译检查，未逐一执行涉及真实数据变化的业务动作。

## 体验入口

开发环境：`http://192.168.10.10:30080/console`。管理员打开“数据与服务”，点击待审核产品的“审核”，再选择“通过审核”或“拒绝审核”。

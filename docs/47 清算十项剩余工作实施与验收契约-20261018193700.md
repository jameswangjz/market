# 清算十项剩余工作实施与验收契约

本文承接41—46号文档，只补充剩余范围，不改变已经确认的业务规则。记录时间为北京时间2026年10月18日；本文是实施契约，不是完成证明。

## 一、实施分组

|分组|关联任务|实现与验收边界|
|---|---|---|
|最终财务基线|CLR2-BE-003、QA-001|一笔退款涵盖多个经济段时，每段独立验证版本切换回执、原最终基线、冻结规则、累计冲回金额与成本；汇总守恒，不能以第一条基线代替全部来源。缺证仅暂挂财务清算，不阻塞获批买方退款。|
|管理入口|CLR2-BE-005、BE-006、FE-003|实际收益主体、产品收益分配、不可返还成本例外申请及对方审批；补差须明确来源、承担主体和证据，批准不等于资金到账。|
|完整报表|CLR2-BE-007、FE-001|平台及提供方权限内显示买卖方、经济段、五方比例与金额、原单及最终基线引用；服务方、专家、渠道仍只能看到自身收益，不泄露成本及其他参与方信息。|
|年度余额|CLR2-BE-009、FE-003|区分业务发生额与资金余额；期初、当期新增、付款、回收、抵扣及期末按实际时间桥接，未知历史明确标识，快照不可变，正式归档不得掩盖未决项。|
|组合验证与运行|CLR2-QA-003、OPS-001|管理页面浏览器验证、交易到清算组合验证、新计费分代真实APISIX调用及采集和退款；分组回归后再做一次发布验证。|

## 二、不可放宽的边界

1. 产品成本全部归提供方；成本与利润可合并付款，必须分项记账。
2. 最终清算调整不能改写实际收款、买方退款上限；补差责任与现金证明分别管理。
3. 多源负向清算须保存逐源不可变证据。累计校验同时计入既有单源退款、版本切换冲回和新增多源冲回，不可重复使用来源余额。
4. 未决成本例外不得猜测分配到不同经济段；无法精确证明时保留明确的待处理原因。
5. 资金凭证须不同操作人复核；草稿不改变余额；模拟和人工确认不表述为银行对账成功。
6. 年度资金时间使用已确认分配的实际确认时点；年末以后发生的付款不得提前扣减历史年末余额。未冻结基线或缺失资金证明不能按零填充。
7. 新计费分代验证不得删除旧流、新流、游标或缺口审计。测试业务必须独立标记、可追溯，受保护订单ORD-261012005144E1B3及其依赖不得修改。
8. 不新增自动月结任务，不自动确认或付款，不替用户验收。

## 三、测试安排

先做各模块针对性测试，再做财务组合与浏览器组合。小型样式或字段改动不重复全平台回归。

|测试组|重点场景|
|---|---|
|多源退款|两段及以上、不同最终比例、累计分币、重复段、来源篡改、超额、证据缺失、幂等重放|
|管理权限|平台和提供方隔离、收益主体仅自身、不得自审、失效身份、重复提交、不同企业上下文|
|报表年度|跨12月/1月、上年应付本年付款、上年负向本年追回、抵扣、未知历史、快照冻结与正式归档门禁|
|真实计费|真实网关请求产生事件、新分代采集落库、实际扣减计量、退款权益回收、旧流及缺口保持不变|
|浏览器|管理入口操作、检索分页、证据追溯、移动与桌面布局、错误提示、退款至清算关联|

## 四、进度与证据

开发控制台保留10项进行中及原百分比，启动不等于完成。仅在代码、专项验证、相关运行验证均有证据后转为待验收。后续验证报告列出实际执行命令、结果、版本及未覆盖边界；本文不预填测试通过数。

# 升降级 Saga 与月度清算接入

## 1. 业务范围

支持 API、模型 API 和 SaaS 当前剩余期限及未来已支付续费期限的版本变更。订阅组合、服务起点、到期时间、订阅月锚点及已用量不因版本变更而重置。保留原订单收入、成本、版本和清算规则快照，不直接改写历史已付款业务。

本批资金验证沿用模拟支付、人工到账确认和模拟关联退款；真实支付渠道及银行账未接入，不将内部资金记录当成真实外部转账。

## 2. 三类记录

| 记录 | 用途 | 是否直接进入月度分账 |
|---|---|---|
| 原购买、续费订单及支付 | 原始购买事实，保持冻结 | 按原支付月份正常计入 |
| 版本变更差价支付单及关联退款 | 用户净差额收付及失败补偿 | 不作为完整商品收入再次计入 |
| 版本变更经济调整 | 原版本剩余收入成本冲回、目标版本剩余收入成本计入 | 已入账后按入账时间计入 |

每段经济调整的利润为收入减成本；原版本负向分录使用当时有效的原规则，目标正向分录使用本次报价冻结规则。不能把净差价再扣除完整目标版本成本。正常退款负向清算与版本变更关联退款必须分类排重。

## 3. 有效期限段与连续变更

原订单快照不可变；每次成功切换为当前及未来期限段追加有效经济、交付配置和版本修订。再次变更从上次生效版本的完整等价收入成本及规则计算剩余部分，不再反复冲回最初版本。期段日期保持原值，通过同一订阅月周期标识保留配额已用量。

目标版本价格成本为月度金额，按照原期限段购买月数计算完整等价金额，再乘该段剩余比例。未来尚未开始的期限段比例为 1。金额采用 Decimal，按分取整；多段差额相加得到净应付或净应退。

## 4. 持久化流程

创建请求前重新验证五分钟内的签名报价、买方、企业、组合及所有期限段。幂等键绑定报价和来源；同一组合同时最多一个未结束变更。存在变更时禁止新购买、续费及竞争性的支付、退款、版本切换，防止冻结报价与资源状态不一致。

升级：待支付 → 差价支付确认 → 待资源切换 → 实际切换及读回验证 → 更新有效期限修订、提交经济调整 → 完成。

降级：待资源切换 → 实际降级及读回验证 → 提交低版本权益 → 关联原支付及历史升级支付生成净退款 → 退款完成 → 提交经济调整 → 完成。退款失败保留低版本权益和退款待处理状态，不自动恢复高版本。

无差价：实际切换、验证后直接更新权益和经济调整，不伪造零金额支付或退款。

外部调用前提交操作意图、请求标识和非敏感恢复信息；重启后用同一幂等键继续，不凭本地成功标记跳过外部验证。后台 Worker 通过租约和业务锁领取阶段，短事务保存结果。自动失败以 10 秒间隔最多三次尝试，之后进入异常或补偿阶段；人工重试仍需权限、幂等和审计。

升级资源切换失败时先恢复原资源并验证，再退还差价、作废未入账分录。降级或无差价在尚未成功验证目标资源且尚未退款时，失败也须恢复原资源；已验证降级进入退款阶段后不得走该恢复路径。补偿失败须明确异常，不能展示为已成功退款或已恢复。

## 5. 资源适配

API/模型 API 使用真实 APISIX 路由、健康检查、Consumer 和 Redis 策略读回验证；迁移原企业共享 Key 到目标版本路由，不重新生成密钥，不删除计数，不恢复主动停用凭据。原订阅组合、generation、period_key 和北京时间日桶保持不变，降级后已用量超过额度继续拒绝调用。

SaaS 使用已有平台 OAuth 调用 CHANGE，再通过 STATUS 验证租户、企业、产品、订阅、目标版本、管理员及 OIDC 配置；不创建第二个租户，不仅依据 CHANGE 返回码判为成功。

恢复计划不保存明文 API Key、OAuth Secret、Token 或敏感原始异常。资源证明由内部适配器生成；公共请求不能提交或伪造资源成功证明。

## 6. 月度清算

只选择 posted 状态、posted_at 位于所选月份半开区间的经济调整。每条原版本或目标版本分录生成独立、可追溯的清算单和五方明细；保留 signed 收入、成本、利润和分成。累计入批次总额、利润及现有报表。

调整分录与清算单建立唯一来源关系，重复请求不重复计入。允许未确认批次重算时将旧批次关联作废或复用受控清算身份；已确认、进入付款及已付款批次不被改写。普通订单再次生成清算时不得把版本调整单当成原始清算单并作废。

## 7. 权限与界面

已实名买方企业超级管理员、管理员可提交变更及查看进度；仅买方企业超级管理员发起差价支付，平台财务或系统管理员保留人工到账确认。提供方和其它企业用户不得查看买方变更详情；买方列表、详情和界面不返回成本、内部资源计划或凭据。

订单详情保留报价预览，新增提交变更、差价支付、阶段进度、失败信息和刷新。待处理请求按需轮询，切换订单或关闭页面立即停止或丢弃旧响应。状态以中文展示，不将服务器尚未完成的阶段表现为“完成”。

| TRD-BE-018 | 有效期段修订、连续变更经济调整、月度入批 | 原快照不变、正负守恒、不重算成本、不重复 |

## 9. 接口与运行组件

| 接口 | 用途 |
|---|---|
| POST `/api/orders/{order_id}/version-changes` | 提交签名报价和幂等键；相同已受理报价可重复查询原请求 |
| GET `/api/orders/{order_id}/version-changes` | 查询该订阅组合的变更历史 |
| GET `/api/version-changes/{id}` | 查询资金与资源处理进度 |
| POST `/api/version-changes/{id}/start-payment` | 企业超级管理员发起模拟差价支付 |
| POST `/api/version-changes/{id}/confirm-payment` | 企业超级管理员模拟确认或平台财务人工确认 |
| POST `/api/version-changes/{id}/retry` | 平台授权角色重试异常阶段，不允许跳过资源验证 |

`version-change-worker` 独立运行在 market 命名空间，与 API 使用相同的已测试镜像和数据库。请求租约、恢复计划、退款来源关联、期限修订及经济调整均持久化在 PostgreSQL；Worker 空闲时仍更新心跳。部署脚本先备份数据库，再更新 API、现有 Worker、新增 Worker 和前端，镜像标签采用 YYYYMMDDHHMMSS-GitSha。

## 10. 明确边界

- 当前资金流程为模拟支付及内部关联退款记录，不调用真实银行或支付机构；不宣称完成真实原路退回。
- 尚未支付的升级请求到报价期限后取消，未入账经济调整作废；不会自动扣款。
- 已发生版本变更的订阅，不能继续套用旧版普通退款算法直接退款。普通退款必须结合有效版本、历史差价支付、既有退款和未用权益单独核对；该能力属于后续 TRD-BE-019，本批采取阻止错误退款的保护，不将其标为完成。
- 自动或人工重试只恢复对应阶段。已验证降级后，即使退款存储失败也不恢复高版本权限。
- 实际环境验收、故障注入和浏览器验收分别记录证据；某一层通过不代表其它层或所有资源类型均已验证。

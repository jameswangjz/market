## 1. 问题与调整

SaaS_APP4原订单 `ORD-261019032206CB07` 已完成模拟支付与自动交付，但登记入口 `/sso/apps` 缺少原模拟服务要求的客户端路径参数，访问返回404。交付原先只核对租户、管理员、客户端及STATUS就绪状态，没有探测登记的入口路径。

本次将业务入口与OIDC客户端ID解耦。模拟服务内部根据公开产品ID查找唯一客户端，再发起原有授权码及PKCE流程。未修改OIDC客户端ID或密钥，也没有改动机器OAuth2签发、缓存、内省及调用方式。

## 2. 可使用的入口

推荐稳定形式：`http://192.168.10.10:30083/apps/{product_id}`。

SaaS_APP4当前登记地址：

```text
http://192.168.10.10:30083/apps/67a69ce54e10fca7f23878ed3524129b
```

平台从订单或“我的应用”启动时，会补入真实 `product_id` 和 `enterprise_id`，替换地址中既有的冲突值，不传密钥或Token。直接打开不带企业上下文的地址，仅展示公开入口页，不会绕过平台认证登录。

登记时暂时不知道产品ID的，可以使用公共入口 `http://192.168.10.10:30083/sso/apps`；平台启动时补入产品和企业参数。第三方必须使用这些上下文选择应用，再以实际OIDC令牌核对身份，不能把URL参数当成授权凭证。

历史 `/sso/apps/{client_id}` 保留兼容，不推荐用于新登记。OIDC协议的授权请求仍会携带公开客户端ID；本次只是从稳定业务入口中移除对它的依赖。

## 4. 新增入口可达性检查

发布接入验证及自动交付最终完成前，调用同一安全探测函数：

1. 按系统HTTP/HTTPS策略校验登记地址。
2. 对协议、主机和路径执行HEAD，单次超时5秒；405或501时回退有界GET。
3. 接受2xx或3xx，但不跟随重定向；404、410、其他失败状态及超时不作为成功。
4. 不发送机器Token、OIDC密钥、用户认证凭据或企业上下文；仅附公开产品ID请求头。
5. 继续使用原有DNS/IP绑定及SSRF保护，不允许任意私网访问。

检查只判断入口路径可达，不验证查询参数驱动的业务、重定向终点、客户端密钥和完整浏览器登录。登录链路须单独验证。自动交付失败继续沿用已有三次尝试及异常转人工机制。

开发环境只额外授权精确主机 `192.168.10.10`，并保留原有 `market-mock-api,market-mock-saas,market-apisix`；没有放开整个私有网段。API、线上交付Worker和应用健康CronJob使用一致策略。

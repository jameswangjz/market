# OAuth令牌撤销部署与实际链路验证

## 部署

环境：`192.168.10.10`，命名空间 `market`。API、消息Worker、线上交付Worker和版本变更Worker已滚动更新为 `market-api:20261013001410-3626b03`。前端无需修改。部署前完成PostgreSQL备份，持久化凭据加密Secret未改变。

## 功能边界

OAuth客户端状态与产品发布状态分别管理。手动下架至草稿只阻止新购买，不撤销已售权益。安全策略下架会停用相关客户端和交付入口。本次修复令牌内省：同时校验签名、有效期、客户端有效状态、产品和Scope绑定，以及持久化Token撤销记录；发放Token增加唯一标识。新增 `/oauth/revoke` 接口，仅保存Token哈希，支持重复撤销。

## 实际验证结果

使用运行中API Pod、真实PostgreSQL、真实OAuth HTTP接口及本地模拟SaaS资源服务，没有替换HTTP接口或内省逻辑。

| 检查 | 结果 |
| --- | --- |
| 同一客户端连续发放Token | 标识不同，内省有效 |
| 撤销前调用模拟SaaS STATUS | 通过鉴权，返回预期的 `404 tenant_not_found` |
| 单个Token重复撤销 | 均返回200，数据库仅一条Token哈希记录，两条操作审计 |
| 被撤销Token调用模拟SaaS | 内省 `active=false`，资源接口401 |
| 同客户端另一Token | 内省仍有效，资源鉴权仍通过 |
| 单Token撤销后重新发放 | 成功，新Token有效 |
| 停用本轮专属OAuth客户端 | 所有已发Token内省无效，资源接口401，新Token申请401 |
| 清理与业务保护 | 本轮专属企业、产品、客户端、配置、撤销记录和测试审计精确删除，其他客户端及受保护订单未变 |

脚本：`scripts/oauth_revocation_runtime_acceptance.py --run`。首轮测试企业ID长度超过字段限制，修正测试脚本后重跑通过；未改动业务数据库字段。后端回归750项通过，44项跳过。

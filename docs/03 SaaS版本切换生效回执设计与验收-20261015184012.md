# SaaS版本切换生效回执设计与验收

文档编号：03。生成时间：2026-10-15 18:40:12，北京时间（UTC+8）。

## 确认范围

用户已确认扩展CHANGE／STATUS，使第三方提供可信的实际版本生效时间。模拟SaaS、平台适配器、经济段核算和提供方可下载规范应一致更新。不支持该回执的应用仍保留人工核定，不以平台查询时间推测生效时间。

## 接口约束

- CHANGE携带平台版本变更标识change_id及方向direction；target表示目标版本，original表示补偿恢复。同一变更的两个方向必须分别幂等。
- CHANGE返回change_id、direction、effective_at。effective_at必须为带UTC时区的实际生效时间，不是请求接收或状态查询时间。
- STATUS返回当前版本及最后一次实际版本切换的同组回执；用户、部门等操作不得覆盖版本切换回执。
- 相同幂等键及参数重试返回首次响应，包括首次effective_at；相同幂等键配不同参数拒绝执行。重启不能丢失回执。
- 平台核对租户、订阅、企业、产品、版本及既有管理员/OIDC身份，并检查CHANGE和STATUS回执匹配。字段部分缺失、时间无时区、标识错配或不可信时间不得降级为自动核算。
- 两个响应均缺少扩展回执的旧应用可维持既有兼容流程，但不得生成可信经济窗口或开放跨版本自动退款试算。

## 数据及资金约束

SaaS回执绑定版本变更、订阅及配置快照，不伪造API凭据、Redis来源或Stream水位。不可变经济窗口使用实际生效时间及冻结的收入、成本、清算规则；当前与未来续费段分别核算。补偿回执与目标回执隔离，失败或已补偿的变更不能作为成功版本窗口。

资金来源继续复用同一订阅组合的原支付和可信升级补款，申请预留、审批复核并冻结。资金退回顺序不改变经济段冲回规则。本增量不实现BE-012退款执行，不能将审批冻结表述为退款到账。

## 针对性验收

1. 首次CHANGE与STATUS返回相同实际时间；重复CHANGE及模拟服务重启后仍一致。
2. 同幂等键不同参数冲突；恢复原版本有独立方向及回执，普通用户/部门同步不改变版本回执。
3. 标识、方向、版本、租户或时间不匹配，以及部分缺字段时，平台拒绝生成可信经济窗口。
4. 缺少全部扩展字段的历史应用保持人工核定，不能伪造生效时间。
5. SaaS剩余经济段按实际生效时间计费；不能调用API水位统计，也不能重扣已冲回的成本。
6. 回执、窗口及审批事务回滚和幂等约束保持；API原有回执和用量统计不回归。
7. 提供方标准、内部标准及前端下载内容同步；文档注明真实执行仍未开放。

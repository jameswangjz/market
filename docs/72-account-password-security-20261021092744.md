# 账号密码修改与找回

## 功能与入口

- 登录后：后台左侧底部“修改密码”；所有有效账号可操作，不要求先完成实名。输入原密码、新密码和确认密码。
- 忘记密码：工作台登录页“忘记密码”；输入用户名、邮箱或手机号码，验证码发送到该账号已验证的邮箱。填写邮件验证码、新密码和确认密码。
- 新密码8～128位，至少包含字母和数字，不得与原密码相同。成功后清除临时密码，所有旧平台登录Token失效，重新登录。
- 找回密码不激活待激活账号、不恢复禁用或删除账号、不修改企业成员或实名信息。
- 邮件使用“系统设置”现有SMTP配置；不使用固定开发验证码，不返回验证码或密码。没有已验证邮箱的纯手机账号暂不支持自助找回，可正常登录后修改密码。短信找回需后续接入可信短信服务。

## 设计

新增password_security表，以user_id为主键，保存密码变更时间、重置验证码HMAC、验证码目标邮箱、请求/失效时间和错误次数，不保存明文验证码或密码。

- POST /api/auth/change-password：必须登录，原密码匹配后变更；连续5次原密码错误，锁定该入口10分钟。
- POST /api/auth/password-reset/request：匿名，账号存在且有效、邮箱已验证并配置SMTP时发送真实随机六位验证码；10分钟有效，同账号10分钟内不重复发送。未知账号、未验证、禁用、待激活、配置缺失与发送异常均返回相同通用提示，不公开账号存在性。
- POST /api/auth/password-reset/confirm：匿名，验证码最多5次错误、仅一次有效；目标邮箱变更后旧验证码失效。
- 新登录Token增加密码版本指纹；密码发生变更后，current_user拒绝所有旧版本或缺少指纹的Token。未变更密码的历史登录保持兼容。第三方机器OAuth客户端和已发放的业务API凭据不受影响。
- PostgreSQL事务锁定用户记录，刷新身份缓存后再校验密码，串行化同账号密码操作；成功变更和邮件发送失败记录审计，不包含密码、验证码或SMTP密钥。
- 前端统一使用现有modal-scrim/modal-card样式，点击弹框外部不关闭；请求期间防重复提交，失败保留输入，成功清空敏感输入。

## 验证范围

聚焦验证原密码、密码强度、旧密码和旧Token失效、新密码登录、验证码哈希/过期/错误限制/单次使用、邮箱变化、临时密码清理、SMTP异常不泄露信息、审计脱敏，以及前端入口/提交载荷/弹框编译/重复提交防护。

隔离测试使用模拟SMTP，不向真实用户发送重置邮件，不改变已有用户密码。真实邮箱收件效果取决于开发环境SMTP配置及邮件服务可达性，不能以模拟测试代替真实收件验收。

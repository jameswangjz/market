## 2. 本轮完成内容

1. 退款按最终确认的清算基线逐经济段冲回，精确关联原订单、原清算单、原批次、支付来源和证据；累计分币、预算、并发和重试受控。
2. 外部补款额外冲回部分形成原付款方返还应付，可抵扣或人工登记后独立复核，不增加买方退款，不混入五方利润，也不自动视为银行到账。
3. 不可返还成本按段提交金额及证据，由对侧整单审批；前端读取原始退款成本依据，不误用例外应用后的值作为上限。
4. 升降级时原版本未使用补款随旧侧冲回。外部补款返还原补款方；平台吸收则恢复内部权益。两者均不转入目标版本，不改买方版本差价。
5. 新版本后续退款不重复继承旧补款；缺证时拒绝提前锁定，核验后可重试；冻结证据纳入重建保护。
6. 报表、导出及前端区分买方退款、财务冲回、外部返还和内部恢复。外部返还付款单独成组、仅人工登记；内部恢复不可登记外部付款。买方及跨企业不能获取提供方成本。

示例：实付150元另补10元、最终清算160元，买方退款30元，财务冲回32元，额外2元属于原补款方返还权益，买方仍只退30元。

## 4. 前端验收

1. 清算分账 → 报表与资金 → 清算报表：查看订单明细中的买方现金退款、财务冲回、原补款方返还权益和来源证据。
2. 清算分账 → 报表与资金 → 主体与成本例外 → 成本例外：选择符合条件的退款，逐段录入保留成本及证据，交对侧审批；普通单段、多段和补差来源均有对应处理。
3. 清算分账 → 报表与资金 → 应收应付：在批次已确认的前提下，选择返还应付登记人工付款，再由另一名有权限的平台人员在资金凭证中复核。存在准确来源抵扣条件时应先抵扣。
4. 清算明细中的版本变更资金投影：外部返还与内部恢复须分别展示，内部恢复不能外部付款。
5. 开发进度控制台：检查两项任务的待验收状态，再根据实际前端检查确认验收。

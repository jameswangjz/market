# 清算分账详细开发设计

生成时间：2026-10-18 17:20:41，北京时间。需求依据为同目录41号完整需求V2。月度清算仅手动触发，不新增月度定时生成任务。

## 1 分层与边界

沿用FastAPI、SQLAlchemy、PostgreSQL和Vue；不重写既有订单、退款执行Saga和清算提案。新增`settlement_finance`负责最终基线与资金台账，`settlement_reporting`负责授权内全量统计及年度快照。原清算单、规则、批次和提案页面保留，新工作区承接报表及资金处理。

模块遵循`install(ns)`模式；函数不擅自提交调用方事务。新表由现有元数据初始化创建，不删除旧字段和记录。GET报表及台账接口只读，不能在读取时回填历史付款或生成债务。

## 2 最终清算基线

每张已锁定清算单保存唯一不可变基线，包括订单、原清算单、原批次、收入、成本、利润、五方实际金额、实际主体、币种、版本标识、确认时间和内容摘要。验证收入减成本等于利润，分成总额等于利润。

基线使用双方最终批准并锁定的数值，不重新读产品现价和当前规则。历史已付款单只有在明确的迁移操作及凭证核验后建立正式资金台账，不能仅根据`paid`推定有银行到账事实。基线被退款引用后，禁止重算静默作废，需走关联补充调整。

零利润保留成本应付和零金额分成解释。所有金额使用Decimal，接口以定点字符串返回；尾差按统一确定性算法分配。禁止用未满100%的比例补齐大额差额。

## 3 应付应收模型

新增最终基线表、资金头寸表、凭证表、凭证分配表及退款基线关联表。头寸按清算单、成本或利润、真实参与方、币种和方向唯一关联；本金及利润各自分项，提供方付款可以在同一凭证合并。

正向单创建提供方全部成本应付和利润分成应付；平台自身分成是内部归属。负向单冲回本金和利润，针对同一来源未付部分形成明确抵扣核销，已经支付的部分保留应追回。不能把未付款冲减当作现金回收。

余额来源为不可变凭证分配之和，不允许直接编辑余额。人工付款、回款和抵扣均需引用、说明、金额、操作者、复核人及审计。凭证区分manual和simulated，不提供冒充真实银行付款的默认值。

凭证生命周期为草稿到已确认，失败不提交金额；提交和确认有版本及幂等键。草稿不改变余额，确认时按稳定顺序锁定头寸，重新校验余额、主体、币种、方向和金额。复核人与创建人不得相同。跨主体或跨币种抵扣拒绝。

## 4 退款与例外

买方退款执行保持资源回收、冻结资金来源和模拟资金回执现有顺序。普通退款完成后进入月度清算候选；不因原清算未确认或对手方未回款而重新阻塞已批准的买方退款。

存在唯一、匹配经济段的最终基线时，累计收入、成本和每个参与方金额使用累计比例差额计算，本次等于新的累计目标减此前确认冲回，最后一次全退以原实际金额结清尾差。原清算比例或金额经调整后必须使用最终数值。

无最终基线的负向单明确标为待基线确认，可显示试算但不能锁定、付款或称资金已结清。原基线就绪后由受控刷新操作重新计算，并记录前后值和关联版本。跨版本必须匹配原经济段，不允许退化为把任意一张正向清算单当成全部基线。

不可返还成本例外使用独立申请与批准记录，保存证据、核定金额和承担主体。未批准不得影响计算；例外的成本、利润及参与方影响需明确列示，不直接改变买方批准退款金额。若例外带来损失，必须明确承担主体，不默认为普通参与方应退更多资金。

## 5 接口契约

| 接口 | 职责 |
| --- | --- |
| GET /api/settlement-finance/positions | 授权内成本和利润头寸、余额、分页及全量汇总 |
| GET /api/settlement-finance/transactions | 凭证列表、付款与回款及抵扣状态 |
| POST /api/settlement-finance/transactions | 幂等创建草稿，kind为payout、recovery或offset |
| POST /api/settlement-finance/transactions/{id}/confirm | 不同操作者复核，锁定余额并原子记账 |
| GET /api/settlement-reporting/report | 全量金额及数量聚合，明细单独分页 |
| GET /api/settlement-reporting/export | 过滤范围全量CSV，不受当前分页限制 |
| GET POST /api/settlement-reporting/annual-reports | 授权内年度快照查询或按需生成草稿 |
| GET /api/settlement-reporting/annual-reports/{id}/export | 受控下载不可变报告快照 |

查询统一支持`enterprise_id`和`business_view`，平台范围不依赖客户端传入企业ID授权。资金写接口不向提供方开放。待完成的主体配置、成本例外、基线受控刷新和年度正式归档接口在对应任务中补齐并验证，不因存在此表而称已实现。

资金头寸字段包括id、settlement_no、order_no、participant_type、participant_name、kind、direction、amount、applied_amount、balance、status和currency。凭证写入包含request_id、kind、mode、reference、note及allocations，每项为position_id和amount；抵扣附counter_position_id。确认请求含expected_version、request_id和note。

## 6 授权与主体

平台系统管理员、运营和财务按既有清算角色进行管理，安全审计角色只读。已实名有效提供方企业超级管理员和管理员只看当前企业提供的产品；买方和普通成员不得通过过滤或导出获取成本、利润和他方信息。

专家、渠道、数据服务方需实际收益主体及独立授权；现存数据缺少主体时，显示未配置并阻止付款，不擅自将所有专家视为同一人。主体映射变更必须版本化，旧基线不追溯改变。完整主体配置和第三方收益门户是独立开发任务，不以平台报表可见替代。

## 7 报表定义

过滤必须在聚合前执行。后端读取完整筛选范围，金额用Decimal；收入业务订单按正向原业务订单去重，退款按完成退款单去重，版本变更按变更事件去重而非双腿计数，另列清算记录数和去重关联订单数。

月份使用有效月度批次period_start作为归属时间，未入批的记录以业务或创建时间明确标识。查询区间按北京时间自然日转换，结束日期以次日00:00不含终点处理。过滤状态与未确认记录必须在输出中说明。

统一输出总体、月份、提供方、产品版本、参与方、贡献排名及订单明细。提供方成本加利润分成应收单列，平台利润不使用全部利润冒充。涉及旧单主体不完整、基线未确认或资金未登记时明确未知或待确认，不推定已付。

CSV使用标准csv.writer、UTF-8 BOM、中文字段并防止文本公式注入。导出覆盖全部授权过滤范围；超过同步能力显式转异步任务或拒绝，不静默截断。年度快照固定范围、规则、包含记录、版本和摘要，草稿不称正式会计年报；正式复核和归档需检查未确认及未结清事项。

## 8 前端工作区

保留现有清算单详情、调整提案、规则和手动批次入口。新增统一工作区，以标准ConsoleTabs展示清算报表、成本与分成台账、资金凭证和年度报告。提供方仅显示授权内报表和头寸，不出现平台资金写按钮。

使用统一检索和分页组件，12px紧凑表单，桌面流式宽度、窄屏表格容器滚动。付款、回款及抵扣使用一致风格弹框，填写凭证、原因和金额，提交防重并在网络重试中复用幂等键；换企业、换账号或关闭页面丢弃旧响应。

## 9 兼容与部署

不自动回填历史paid为真实付款，不删除清算或订单数据。历史基线、供货成本应付、参与方映射和欠款迁移另行只读盘点，出具清单并经确认后执行。受保护订单ORD-261012005144E1B3及依赖产品保留。

新代码经隔离数据库验证，再部署market命名空间。镜像标签采用YYYYMMDDHHMMSS-GitSha，产物从已提交代码可信重建。部署前备份数据库和K8S清单，应用健康后核对任务、主体授权和关键接口；失败回退镜像，不对新业务表执行破坏性回滚。

## 10 验证与进度

每个模块测试涵盖金额守恒、不可变基线、过期版本、幂等、权限、并发与异常回滚；多功能就绪后再执行购买、退款、清算和报表组合回归。报表专项必须包含超过2000条及多次部分退款、双腿升降级和相同名称不同主体。

任务子步骤在开发进度控制台展示；定义性子步骤不伪装成已执行记录。只有验证证据完成才转待验收100%，用户验收后再完成。无法验证的真实银行、历史迁移和真实第三方回款分别列示，不因模拟链路通过而一并关闭。

## 12 状态与事务边界

|对象|允许变化|触发及保护|
|---|---|---|
|清算批次|generated → pending_confirm → confirmed → paid|关联清算单全部锁定后可待确认；确认需无待处理提案；paid仅表达正向付款完成，不表示负向款已追回|
|未确认批次|generated/pending_confirm/rolled_back → superseded|重建保留旧清算单、基线和审计；已有实际核销或退款引用时须另行调整，不得销毁资金依据|
|清算单|pending/adjusted/proposal_rejected → locked|存在未处理提案不允许锁定；已锁定金额保存最终基线；退款无可信基线时仅阻止清算锁定，不阻止买方退款|
|正向清算单|locked → paid|批次资金证据满足要求；成本与利润资金行已付款或合法抵扣|
|负向清算单|保留清算确认状态，资金进度独立|应追回、已追回、已抵扣、未追回分别展示，不能随批次按钮直接改成“款已追回”|
|资金凭证|draft → confirmed|草稿只保存计划；另一操作员复核，二次锁行校验，成功后追加核销和审计|
|退款清算评估|waiting/unsupported → ready|锁定前重新验证原资金/资源证明和最终基线；追加评估版本，不改写原退款执行证明|

凭证确认的原子事务包含：检查幂等键、锁定凭证、按稳定ID顺序锁定涉及头寸、检查批次及余额、追加复核、追加各行核销、追加幂等结果和审计。任一步失败全部回滚。不同草稿争用同一余额时，仅允许余额充足的操作成功；同一请求重试返回同一结果。

清算收入与已确认支付记录不一致，且没有明确补差来源时，记录阻止原因`unfunded_settlement_adjustment`，不能因调整提案获批就凭空增加可付资金。补差来源登记及承担主体的完整审批是后续受控业务，不使用修改Payment或订单实收来规避。

## 13 请求与返回示例

主体配置接口包括`GET/POST /api/settlement-parties`、`GET/POST /api/settlement-parties/products/{product_id}/allocations`；同一分成类别多个主体权重合计为100。成本固定归原提供方，不用于重新配置成本所有者。

例外申请接口为`GET/POST /api/settlement-cost-exceptions`及`POST /api/settlement-cost-exceptions/{id}/decision`。申请包含refund_id、retained_cost、reason、evidence_refs、bearer_participant_id及request_id；审批包含decision、expected_version、request_id、reason。审批留证不等同于例外金额已经应用到资金台账，必须以对应任务和验证结果为准。

提供方成本和利润合并付款仍保持两个独立分配项：

```json
{
  "kind": "payout",
  "mode": "simulated",
  "reference": "SIM-RECEIPT-EXAMPLE",
  "note": "成本和利润合并付款验收样例",
  "request_id": "unique-client-request-id",
  "allocations": [
    {"position_id": "provider-cost-position", "amount": "100.00"},
    {"position_id": "provider-profit-position", "amount": "40.00"}
  ]
}
```

创建返回id、kind、mode、reference、creator_id、version、status及allocations。复核请求使用`{"expected_version":1,"request_id":"another-unique-id","note":"独立核验"}`。同一操作者不能复核自己的草稿；模式为simulated时绝不返回银行回执已验证。

报表日期参数只接受YYYY-MM-DD，结束日包含当天。source_kind仅使用original、refund、version_change。响应包含summary、monthly、products、providers、participants、rankings、items、total、page、page_size及scope；资金未知使用null与原因，不能用0代替。参与方分别提供cost_amount、profit_share和total_receivable。资金执行与账务金额均返回精确字符串，前端不以浮点数重新推算。

错误统一区分422字段或金额格式、403权限或同人复核、404不存在或不可见、409状态/版本/幂等冲突及资金证据不完整。前端把常见业务码翻译为中文；未知业务码保留排查标识，不输出SQL、密码或堆栈。

## 14 金额验收样例与覆盖边界

收入150、供货成本100、利润50，平台20%和提供方80%：平台利润10，提供方成本100与利润40分项，合并应付140。其他方为零时不能伪造收款主体。

退款30，占原收入20%：成本冲回20、利润冲回10，其中平台2、提供方利润8，提供方成本与利润合计冲回28。若提供方未收款，则对应28冲减未付；若已收款，则28是应追回，未登记回款前不能称已追回。退款后净收入120、净成本80、净利润40，提供方净应收112、平台内部净收益8。

最终确认成本调整为80、利润70而实收仍150时，退款30应使用最终成本80的20%，即冲回成本16、利润14，不再使用原登记成本100。收入、成本或参与方金额被最终调整后，每次退款均需保留最终版本引用和审计。

专项覆盖包括：分币累计全退不溢出、不同人复核、幂等冲突、并发超付拦截、核销与审计事务回滚、未确认批次重建后旧头寸不可付、旧已付不得自动迁移、不同企业报表隔离、2007条全量汇总导出、中文/逗号/换行及CSV公式防护、真实浏览器合并付款和跨操作者复核。

跨版本精确经济段最终基线、成本例外金额应用、其他受益主体专属账号门户、跨年余额桥接及线下退款全链路，在尚未有执行证据之前保持未完成。模拟资金验证不替代真实支付/银行和外部参与方返款验证。

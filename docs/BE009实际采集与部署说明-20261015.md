# BE-009实际采集与部署说明

## 运行链路

1. 首次有效支付事务冻结订单SLA承诺、支付来源与交付deadline；历史已支付订单不回填。适配器验证成功后记录首次交付成功，重试不改写。
2. 原生APISIX全局`market-sla-logger`为请求生成服务器request_id，log阶段记录终结状态和有界字段，内存批次进入Redis队列。接收端提交PostgreSQL后ACK，队列再删除；重放按event_id和源序号幂等。
3. 各producer封存五分钟窗口，保存期望序号与接收事实。缺窗、缺序号或无法证明producer生命周期时，保留观测值但返回数据不足，不伪造完整来源。Redis开发部署不具备跨节点持久化保证，不能把此队列描述为已经完成生产级无损灾备。
4. 独立Consumer、HMAC、Pod来源网段和只读健康路径共同限定探测。标准key-auth不绕过；仅服务器验证的探测免买方配额，仍有独立频次桶。API按产品/版本/入口共享事实；SaaS按租户保留隔离。
5. `sla-online-monitor`每五分钟运行探测和在线订单评估，`ticket-sla-monitor`每五分钟物化工单时钟并去重通知。模型初始化由正常发布启动负责，worker不执行DDL或种子初始化。

## 评估入口

- `POST /api/sla/evaluate`继续支持无请求体，改为按订单原冻结规则考核。可通过year/month查询参数指定自然月；非平台管理角色不可触发全局评估。
- `GET /api/sla/overview`及`GET /api/sla/results`读取在线评估落库结果。旧平台规则结果保留历史标记，不覆盖其原始记录，不混入新达标统计。
- `sla_online_assessments`以订单和自然月唯一标识结果，输入事实变化才递增版本；审计和通知同事务。P95单独返回，不填入平均耗时字段。
- 错误率/P95按购买企业隔离，共用可用性事实也按各订单冻结阈值分别判断。企业后续调级不追溯已有订单。
- 请求指标只读取最近已闭合的五分钟水位，返回截止时间和滞后秒数；交付时钟仍按实际当前时间计算，不能因日志等待而暂停。
- 单笔交付时长独立考核，不套周期10单门槛；周期及时率按deadline归月，失败未完成及退款后已发生的超时不会被抹去。

## 数据不足与适用性

- 有效探测至少100个且覆盖率至少90%；请求至少100个；P95至少100个耗时且完整率至少95%；交付及时率周期至少10单。
- 文件产品不适用API可用性/请求错误率/P95；未开始的未来续费时段不当成源故障。
- SaaS没有授权业务探测或真实业务日志时，明确缺源，不能拿管理接口成功或登录页面200代替。
- 历史订单缺冻结承诺、历史日志缺窗、订阅修订缺可靠生效区间等均保守返回数据不足。当前候选与事实读取尚不是生产大规模增量水位算法，不宣称已经完成容量优化。

## 发布和回退

使用已测试的Git提交，经`trading_artifact_gate.py`干净重建并验证来源后，发布标签必须为`YYYYMMDDHHMMSS-GitSha`。

`deploy_trading_runtime.sh`先备份数据库、再滚动应用；`deploy_sla_runtime.py`再次验证来源，备份现网配置，生成或复用独立Secret，追加网关白名单与来源网段，滚动API/APISIX，启用日志全局规则并应用定时任务。脚本只对业务配置匹配的既有路由补充telemetry标签，不重写上游、鉴权或配额。

Secret不写入源码、命令参数或验证报告。失败恢复本次保存的配置，不重置etcd，不全量删除路由或凭据。数据库新增表为加法变更，未实施破坏性历史迁移。

部署流程在观察旧APISIX Pod确实删除后，为事前记录的producer写退役证据；不凭过期心跳推断故障worker已经退役。新增worker保留独立身份，避免滚动更新后的旧producer无限要求未来窗口。非本流程的异常退出仍保守视为缺证。

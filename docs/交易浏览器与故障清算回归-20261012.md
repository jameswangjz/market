## 执行顺序与验收

1. API/模型API：原订单支付与交付、同凭据升级、差价支付、降级和关联退款，原路由及目标路由实际调用，额度计数连续。
2. 真实账务清算：复制上述已支付订单和 worker 已入账调整，验证原订单与正负调整、五方金额守恒、差价支付及退款排重、重放、重建、确认后不可重建、报表和导出。
3. 重启：持久化资源计划提交后暂停本轮请求，重启真实 worker，恢复同一请求，资金预留不重复，资源切换及计数正确。
4. 故障：仅删除本轮目标路由，观察三次重试、原资源恢复、升级资金退回、调整作废。重新读取实际 APISIX 与 Redis 状态验证。
5. 浏览器：在真实控制台提交升级、完成差价模拟支付、等待 worker 完成，再降级并观察退款完成；桌面与移动窗口检查。若原订单由 API 预置，明确不计作浏览器首购或密码登录覆盖。

# SaaS 接入配置最小化下发与验证

生成时间：2026-10-19 10:52:20，北京时间。

## 1. 已确认的改动边界

本次不是取消机器 OAuth2，也不是停止生成机器凭据。平台继续在 SaaS 完成运营审核后生成或复用产品级机器 OAuth2 客户端，继续保存并使用其 `client_id/client_secret` 获取机器 Token、调用 SaaS 管理接口。

只调整提供方获得的接入文件：不再下发平台内部机器客户端ID、密钥及内部取Token地址；保留 SaaS 服务端必须使用的 OIDC 登录凭据，以及验证平台机器请求必需的元数据。

没有变更现有客户端ID、密钥、签名算法、Token有效期、缓存、内省或机器业务调用方式，也没有重试业务交付订单。

## 2. 下载格式 2.0

统一接口路径不变：`GET /api/products/{product_id}/saas-integration-credentials-download`。前端仍使用“下载接入配置”，文件名称仍为 `{产品名称}-SaaS应用接入配置.json`。

| 分区 | 新行为 |
| --- | --- |
| `schema_version` | 改为 `2.0`，明确表示不兼容旧机器凭据导出结构 |
| `product` | 保留产品标识及应用／管理接口地址 |
| `oauth2_api` | 整个分区移除；不再向提供方导出机器客户端ID、密钥、取Token地址 |
| `resource_server` | 新增 Bearer 认证方式、introspection校验方式、内省地址、issuer、audience及scopes列表，不含客户端凭据 |
| `oidc_sso` | 保留既有客户端ID、密钥、OIDC端点、回调及PKCE参数，值不轮换 |
| `instructions` | 明确平台内部机器凭据与第三方OIDC配置的用途及边界 |

`resource_server.scopes` 是排序后的数组；内省响应里的 `scope` 仍是空格分隔字符串，二者不可混淆。

下载权限不变：仅产品提供方企业已实名、已激活的超级管理员和管理员。平台内部角色、购买方及普通成员仍被拒绝。下载继续禁止缓存并记录不含密钥的审计信息。

下载仍要求平台内部机器客户端有效，不能因文件不下发机器密钥而绕过平台自身认证前提。

## 3. 旧入口与历史文件

SaaS 产品的旧 `/oauth-credentials-download` 在既有提供方权限检查后返回410，并提示改用统一下载；未授权账号仍被拒绝，不能通过旧入口继续取得机器密钥。API及原有model分支的OAuth下载未按SaaS规则改动。

已有1.0格式文件无法远程删除。本次不会自动撤销其中的旧机器凭据；若需要处理既有泄露风险，应另行安排受控轮换，不能为清理文件而直接破坏平台与应用的现有调用。

- `docs/saas-integration-standard.md`：保留的内部标准文件。
- `frontend/public/saas-integration-standard.md`：前端下载源文件。

实际前端下载地址：`http://192.168.10.10:30080/saas-integration-standard.md`。

规范新增2.0文件结构、内省请求及响应示例、HS256机器Token与RS256 OIDC ID Token的区别，以及内部地址不可直接用于集群外SaaS等说明。同步纠正“第三方需配置两套密钥”的旧表述，并说明通用调用使用JSON `idempotency_key`，不能要求每次必有 `X-Request-Id`。

# 初始调用凭据与升降级清算补偿

## 1. 本批边界

本批补齐 API、模型 API 首次自动交付时的买方调用凭据，以及订单页授权下载入口；同时建设升降级正负经济调整台账。台账不等于实际版本切换、付款、退款或清算批次接入，相关任务不得因此标为完成。

代码由 gpt-6-luna medium 编写，主模型负责设计、代码审查、独立验证和部署。现有工具未提供子模型的独立 token 消耗，不能据此报告节省比例。

## 2. 初始凭据

1. 先核验冻结订单、全额支付、版本接入证据、实际健康检查及 APISIX 路由。
2. 在企业和订阅组合事务锁内授予订阅期限，再查询企业、版本路由的共享凭据。
3. 没有历史共享凭据时生成随机调用 Key，数据库保存摘要、前缀及 Fernet 密文；不使用 JWT 签名密钥作加密密钥。
4. 发布 APISIX Consumer 和 Redis 订阅策略，再读取实际配置进行核验。全部成功才完成交付。
5. 同版本续费保留原 Key，不累加月度额度、不重置已使用量。历史停用凭据不因续费重新启用；历史只有摘要的凭据不能反推出原文，不自动轮换。
6. 本批现有凭据仍绑定版本路由；跨版本共享凭据迁移由后续版本切换 Saga 统一处理，不得声称已完成跨版本无感切换。

### 下载及保密

`GET /api/orders/{order_id}/api-credentials/{credential_id}/download`

- 仅当前买方企业的已实名超级管理员、管理员可下载，企业仍须已认证。
- 平台角色、提供方、普通成员及其它企业管理员拒绝访问。
- 验证当前有效订阅、路由、凭据启用状态和有效期，再解密并核对摘要。
- JSON 文件包含调用 Key、Key ID、网关地址、路由及限流配额，不包含提供方接入凭据。
- 响应设置 `Cache-Control: no-store`，以附件下载。列表只提供可下载标志，不返回密文或原文。
- 下载须提交审计记录后才返回文件，审计和通知不包含密钥；前端不存储原文、不自动下载、不在订单列表显示 Secret。

### 故障补偿

在外部 Consumer 发布前登记本次新建 Consumer 的精确标识。任务内部失败、后续审计失败及数据库根事务回滚都清除本次 Consumer 和缓存。内部 savepoint 提交不代表根事务成功。补偿失败必须暴露故障，不能吞掉异常后宣称交付成功。

本批补偿回调在进程内保存；进程被强制终止时不能保证回调执行。持久化外部操作日志、孤立 Consumer 检测和重启后的自动恢复仍归 TRD-OPS-002，不以事务回滚测试代替进程故障验收。

专用 Kubernetes Secret 为 `market-api-credentials`，字段 `API_CREDENTIAL_ENCRYPTION_KEY`。首次配置生成密钥，后续部署必须保留；丢失或更换会导致旧密文无法下载。须纳入备份和受控密钥轮换，不得提交 Git。

## 3. 升降级经济调整台账

`version_change_adjustments` 为内部台账，不直接调用外部资源，也不通过公共接口接受用户提交金额。

每个当前或未来已购买期限段分别记录两条分录：

| 分录 | 收入 | 成本 | 规则 |
| --- | --- | --- | --- |
| 原版本冲回 | 原订单剩余收入的负数 | 原订单剩余成本的负数 | 原订单冻结规则 |
| 目标版本计入 | 目标版本相同时长的剩余收入 | 目标版本相同时长的剩余成本 | 本次目标报价规则 |

利润始终为收入减成本。用户付款或退款为各期限段收入差额之和，不能以净差价代替完整正负收入、成本调整。历史订单和已消费部分保持不变。

状态为 `pending`、`posted`、`void`。请求、来源订单和分录方向设唯一约束；完整报价指纹用于防止同一变更标识复用不同内容。暂存及审计属于调用方事务。资源变更证据通过内部契约后才允许入账；未入账失败可作废，已入账证据不能直接删除或作废，须追加反向补偿。

## 4. 后续 Saga 的约束

- 持久化请求绑定报价 Token、买方、企业、组合、当前及未来期限段；同一组合最多一个未结束的变更。
- 升级先生成并确认净差价支付，再变更网关或第三方资源，核验成功后才切换权益并提交经济调整。
- 降级先核验资源降级，再提交关联原支付的净退款；退款失败进入可重试补偿，不允许悄悄恢复高版本或重复退款。
- 固定每个期限段的收入、成本和规则，不改变原已支付订单快照。重复变更须以已生效版本的经济状态为基础，不能重复冲回首次购买版本。
- 有效期和服务日锚点保持不变；未来已付续费段一并变更，但不提前重置当前额度。
- 同一额度周期保留已用量；降级额度小于用量时暂停调用至下一周期。
- 外部操作使用稳定幂等标识、持久化阶段、10 秒间隔三次重试及人工异常处理。
- 月度清算需纳入已入账调整，并防止与普通退款负向清算重复计算；确认、付款的清算批次不被版本切换重写。

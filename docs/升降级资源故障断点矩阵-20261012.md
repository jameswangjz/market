# 升降级资源故障断点矩阵（2026-10-12）

本文记录本地 worker/adapter 测试替身覆盖的断点，以及已完成的有限真实运行时故障演练。除明确标注为 runtime 的记录外，测试通过不代表已连接或验证真实 APISIX、Redis、SaaS 服务或生产数据库。

## Worker 事务断点

| 断点 | 本地断言 | 测试 |
| --- | --- | --- |
| 资源计划持久化之前/之后 | 首次 worker 周期只生成并提交 descriptor；adapter 尚未被调用 | `backend/tests/test_version_change_fault_boundaries.py::test_resource_plan_is_committed_before_adapter_apply` |
| 外部资源已应用、数据库提交失败 | 有状态 SQLite fake adapter 保留外部应用结果；SQLite 回滚不留下 posted ledger 或 revision；下一次同一 change 重放后只落一条 ledger 和一条 revision | `...::test_external_apply_then_database_commit_failure_replays_without_duplicate_rows` |
| 外部 proof 与 change 不匹配 | worker 进入重试，不改变本地版本，不写 ledger/revision | `...::test_mismatched_resource_proof_never_posts_ledger_or_revision` |
| 退款/补偿阶段连续失败 | 本地异常注入连续三次失败后进入 `exception`；事务回滚，不产生成功的 posted ledger 或 revision | `...::test_refund_failure_retries_three_times_without_successful_posted_financial_record` |
| 资源恢复连续失败及人工重试 | 恢复失败三次进入 `exception`；修复 fake adapter 后将状态重置为 compensating，worker 完成恢复 | `...::test_compensation_failure_exhaustion_and_operator_retry_after_repair` |
| 升级目标资源失败后恢复和资金退款 | 端到端 API/SQLite 集成流程验证恢复原版本、退款、ledger void | `backend/tests/test_version_change_saga_integration.py::test_failed_upgrade_resource_is_verified_restored_and_funding_refunded` |
| 降级资源已应用、退款入账失败 | 保持低版本 revision 与资源状态，退款重试期间不重复写退款 | `backend/tests/test_version_change_saga_integration.py::test_downgrade_refund_insert_failure_keeps_verified_low_revisions` |

专用 fault-boundary 测试使用 SQLAlchemy SQLite 内存库和 `StatefulSQLiteFakeAdapter`。该 adapter 的外部状态只是进程内集合，用来模拟“数据库回滚而外部副作用仍存在”和幂等重放；它不是生产 adapter，也不代表真实 SQLite 文件、PostgreSQL 或远端 API 的行为。operator retry 用直接更新本地测试行模拟，权限/API 路由本身不在该用例内。

| API / model_api：credential 与目标配置约束 | `backend/tests/test_version_change_resources.py::test_api_integration_snapshot_freezes_accepted_quote_identity` 及 adapter prepare/apply 断言 | 覆盖配置快照身份绑定和部分拒绝条件。对生产 credential 被撤销、密钥轮换/不可解密、远端 consumer 状态漂移的完整故障矩阵仍不完整。 |

| SaaS：原购买方 mapping 与多成员环境 | `backend/tests/test_version_change_resources.py::test_saas_prepare_uses_original_buyer_mapping_with_other_members_present` | 数据访问用 FakeDB，未连接真实身份服务。 |

共享 quota usage 的明确现有断言是 API replay 测试里的 `usage_total == '41'`；测试同时检查 quota scope、generation、consumer key 和原路由恢复。它证明 fake Redis 状态下的 adapter 合约，不证明生产 Redis 并发更新或计数器原子性。

- 实际 API credential 在计划冻结后被吊销、轮换、删除、密文不可解密或 hash 不匹配时，各故障时序及人工恢复结果。

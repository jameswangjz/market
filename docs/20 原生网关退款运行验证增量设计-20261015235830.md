# 原生网关退款运行验证增量设计

## 范围

继续 TRD-R3-BE-012、TRD-R3-QA-005、TRD-R3-QA-006。资金使用平台模拟支付；真实银行支付不纳入本轮。保留 ORD-261012005144E1B3 及其依赖产品，执行前后比较保护指纹。

## 运行与隔离

1. 使用部署中的应用代码、PostgreSQL、Redis、APISIX 原生数据面和现有计量入账工作进程。控制面由 TestClient 调用真实处理器，不声称浏览器或 Ingress 端到端覆盖。
2. 创建随机、精确登记的专属用户、买卖企业、产品、版本、订单和凭据。未使用产品保持草稿，未使用版本不启用。
3. 退款执行使用同一正式 worker 实现，但用 Session 查询条件限定本轮 refund_id，以租约排除共享 worker 抢占。测试工作进程的领取时钟提前两小时，业务资源时间不变；不声称验证了部署 worker 的自然领取或进程崩溃。
4. 两次真实网关调用必须经实际计量工作进程写入账本，核验订单、经济段、周期、来源进程及 Stream 水位。不替换实际入账过程，不回退共享 Cursor。
5. 测试价款20元、版本成本5元、月额度10次，实际扣额2次后退款16元。预期保留共享凭据，剩余额度上限2次且已用量仍为2，后续调用429。

## 故障与恢复

仅对自有组合的 coverage hash 做 CAS 修改，将 baseline 从0改为1。先落盘原值，再执行正式资源阶段，验证资金腿尚未完成、完成回执不存在、退款累计为0、原额度未变。finally 精确恢复原值，通过正式 retry 接口恢复执行，并验证幂等重试不会二次退款或再次扣减权益。不得中断共享 Redis、APISIX 或所有退款工作进程。

## 清算验证

完成退款后，以正式负向清算适配器核验唯一负向单和不可变关联。预期收入-16元、成本-4元、利润-12元；平台、提供方、数据服务方、专家、渠道分成分别为-2.4、-6、-1.2、-1.2、-1.2元。报表与CSV只提取本轮订单和退款，不输出其他业务内容。

适配器是否本次创建负向单须如实记录，不推断退款 worker 已自动产单。此场景不生成或重建用户当前月份清算批次，也不代替跨月升降级完整回归。

## 清理与保留

- 私有清单0600，精确主键登记在外部资源创建和删除之前。旧夹具私有清单在滚动发布前备份到开发主机，不依赖被替换Pod的临时目录。
- 先等待专属事件入账，再锁定根对象复验；锁内不等待可能依赖同一外键的计量入账。PostgreSQL锁等待最多10秒。
- 逐行验证外键，按依赖逆序清理。共享服务等级只读引用和已证明的自有消息收件回执采用窄例外，不删除共享目录或收件人用户。
- APISIX仅删除已证明的专属路由、消费者和健康探针消费者；Redis仅删除专属键、逐条XDEL已验证事件，禁止清空Stream、重置来源epoch或回退Cursor。
- 全局SLA logger仍可能采集本轮业务和探测请求。其不可变事实按event_id、内容哈希、产品、版本、路由精确登记并保留；不修改全局source windows及其封存计数，不宣称SLA验证通过或所有测试痕迹物理清空。
- 自动生成的自有SLA评估、提醒和消息纳入严格归属清理；未知关联拒绝删除，不因结项而扩大清理范围。

## 已实现

- 买方已实名企业超级管理员/管理员发起售后，提供方响应、要求资料、提交解决方案，买方补充、拒绝或确认。
- 双方申请平台介入；系统管理员、平台运营和交付监控审查。只有系统管理员/平台运营可强制关闭，原因必填，不伪造买方验收。
- 服务端返回allowed_actions，前端依当前状态显示动作。版本冲突要求重新确认，网络重试沿用幂等键。
- 不可变评论、按工单控制的附件上传下载。附件上限20MB，真实病毒扫描通过后保存至MinIO；关闭工单仅可追加审计评论用途附件。
- 审计、工单事件、SLA时钟和通知Outbox按事务一致提交；评论和附件不冒充提供方首次响应。
- 展示ORD订单号、中文状态、操作者姓名、时间、理由、原状态和新状态。买方不返回订单成本、凭证或内部存储路径。
- 输入失败保留、关闭草稿二次确认、HTTP环境请求标识兼容、切企业丢弃旧响应。

## 验收操作

1. 买方企业超级管理员/管理员进入订单中心，对已支付订单发起售后；填写说明，连续点击不应创建重复工单。
2. 在交付与售后的售后工单列表点击工单号，查看详情、记录与附件。未提交输入关闭时应询问是否放弃；取消后保留输入。
3. 提供方响应工单，要求补充；买方补充；提供方提交方案。买方拒绝后回处理中，再提交并由买方确认完成。
4. 任一方申请介入后，平台授权人员响应/审查；交付监控不能强制关闭。系统管理员/运营强关必须填写原因。
5. 上传正常小文件并下载核对；评论应显示具体作者。终态不能再改变处理结果，普通证据附件不能代替审计评论用途。
6. 使用无关企业或普通成员，不应查看/操作该工单。并发修改得到409后应核对最新状态，不自动重复提交动作。

不要使用受保护订单`ORD-261012005144E1B3`及其依赖产品做修改测试。

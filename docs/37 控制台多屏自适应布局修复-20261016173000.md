# 控制台多屏自适应布局修复

## 问题与参考

笔记本显示正常，外接大屏后台主内容区居中留出大量空白。当前普通内容区最大宽度1500px，系统设置最大宽度1280px；额外的DPI、宽高比与高度判断会再次缩放页面。

参考项目dev分支 `dcaef1d75bcc78837e1398d812de3a85926eb671` 的 `frontend/src/components/layout/AppLayout.vue` 使用 `flex-1 min-w-0` 填满侧栏外的空间，未给主内容区设置固定最大宽度。参考地址：https://github.com/simcbrcorex/agentic-platform/blob/dcaef1d75bcc78837e1398d812de3a85926eb671/frontend/src/components/layout/AppLayout.vue 。

## 设计与范围

1. 后台所有页面的主内容区占满可用宽度，保留适量内边距；取消普通页及系统设置的最大宽度上限。
2. 字号不随屏幕宽度改变。取消应用层按DPI二次zoom，尊重系统和浏览器的原生缩放，同一CSS视口在不同DPR下布局相同。
3. 侧栏展开、折叠及移动端抽屉保持既有规则，表格在自身容器内横向滚动。
4. 弹框及表单自身的阅读宽度限制保留；公开商城不在本次修改范围内。
5. 同一窗口改变视口尺寸无需刷新；不要求所有屏幕物理字体大小完全相同，该大小仍受操作系统缩放与浏览器缩放控制。

## 任务与验收

- RSP-FE-001：全宽布局及原生DPI适配。
- RSP-QA-001：局部测试与实际浏览器多视口检查。
- RSP-OPS-001：仅前端部署，最终交由用户实际双屏验收。

验证矩阵：1366×768（DPR1.25）、1920×1080、2560×1440（DPR1和2）、3440×1440、900×1200、390×844，再返回笔记本视口；另外检查侧栏折叠以及订单、网关、SLA、系统设置。

浏览器仿真覆盖布局及DPR变化，不能替代真实笔记本与外接显示器的物理显示校准。用户可将同一浏览器窗口在两块屏幕间移动，确认主内容区填满可用宽度、分页和弹框正常。

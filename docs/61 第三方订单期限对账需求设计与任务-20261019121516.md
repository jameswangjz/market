# 第三方订单期限对账需求、设计与任务

生成时间：2026-10-19 12:15:16（北京时间）。

## 1. 目标及边界

SaaS及API提供方应能区分每笔订单的权益时段、租户或订阅组合的最终截止时间、版本变更实际生效时间及退款后的截止时间。OAuth令牌过期时间不代表业务期限。

本次仅补充业务上下文、模拟服务回执及只读权益对账能力，不改变已确认的价格、成本、退款、配额和清算算法，不接入银行对账，不修改历史订单快照，不重发历史操作，不轮换凭据。

## 2. 时间语义

- 所有对外时间采用带时区的UTC ISO 8601；有效时段为左闭右开。
- 订单时段对应该订单实际获得的服务区间，续费订单不覆盖原订单。
- 组合最终截止时间包含已经交付的后续续费权益，不因单个订单结束而错误停用整个租户。
- 开通准备阶段尚未确定实际交付时间时，应标为待确定，不编造实际起止时间；激活阶段发送冻结时段。
- 升降级影响多个已购买时段时，应列出受影响订单及其时段，原订单信息与当前有效版本不能混淆。
- 退款携带原截止、新截止及退款关联；第三方返回实际执行结果。回传请求字段只是关联证据，不等同独立资金到账证明。

## 3. 应用设计

采用附加的、带版本的对账上下文，不覆盖既有管理接口业务字段。SaaS开通、激活续费、版本切换、退款缩期、用户及部门同步使用共享构造逻辑。租户级操作允许没有单一订单，不强行关联最近订单。

新操作在持久化请求时冻结上下文；重试必须复用原请求。旧已准备或成功的操作保留原字节语义，不为增加字段而产生幂等冲突。第三方模拟服务保存变更回执，重复请求返回首次结果，状态查询可查询最近生效上下文。

API实际期限仍由平台网关控制。提供方使用受权限限制的只读分页查询了解订单及有效时段；该查询不创建新授权、不扣配额、不改变订单或清算。产品归属、企业管理员权限与机器认证必须分别验证，不能用购买方API Key读取提供方账本。

## 4. 安全与兼容

对账数据不包含客户端密钥、买方API Key、用户密码、买方个人资料及内部成本。产品提供方只能读取自身产品；普通企业成员不能通过知道产品ID越权查询。时间和标识格式错误应明确拒绝，不推断缺失日期。

| REC-DOC-001 | 提供方规范及实际下载文档 | BE-001、BE-002 |
| REC-OPS-001 | 部署及运行核验 | QA-001、DOC-001 |

## 6. 验证范围

分组验证首次开通及续费、升降级及退款、成员部门同步、提供方查询隔离及分页；完成组合后统一回归。重点覆盖旧请求重试、新请求字段冻结、未知期限、UTC边界、错误订单关联、多时段和权限隔离。不得为验证修改现有真实订单或受保护订单。

任务状态以控制台及最终验证报告为准，未执行的运行验证不得标为通过。

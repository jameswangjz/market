# 浏览器登录桥接、模拟 SaaS 会话与用户应用访问

## 1. 边界与组件

平台作为统一 OIDC 身份提供方（OP），SaaS 应用作为资源服务和 OIDC 登录客户端（RP）。机器管理接口继续使用独立的 `client_credentials` 客户端；用户登录采用授权码 + PKCE S256。两类客户端、令牌、Scope 和用途不能混用。协议实现使用 Authlib，ID Token 使用独立持久化 RSA 密钥签名，公开 JWKS 不包含私钥。

新增组件：平台浏览器授权事务、登录确认页、企业购买方应用授权 API、“我的应用”页面，以及带持久化 SQLite 状态的模拟 SaaS RP。已有产品审核、支付、文件下载及 API 凭据权限不因本功能而扩大。

## 2. 浏览器授权流程

1. 用户从“我的应用”启动 SaaS。平台确认企业成员、应用授权和当前订阅有效，返回登记的应用访问地址，并附带企业标识；不携带平台登录 Token、Client Secret 或购买方 API 凭据。
2. RP 服务端生成随机 `state`、`nonce` 和 PKCE verifier，持久化五分钟有效的登录事务，并设置 HttpOnly、SameSite=Lax 浏览器绑定 Cookie。
3. RP 重定向至 `GET /oidc/authorize`。平台检查客户端、精确回调白名单、Scope、响应类型及 PKCE；将请求保存为五分钟有效的浏览器授权事务，仅以随机请求 ID 跳转 `/console/sso?request=...`。
4. 未登录用户先进入平台登录页，登录后回到同源授权确认页。确认页展示应用、企业、账号、权限范围与有效期；用户可以同意或拒绝。
5. 平台确认接口要求有效平台登录会话、浏览器绑定 Cookie 和正确 Origin。事务加行锁，重新检查用户、企业、授权和订阅。签发授权码与消费浏览器事务在同一事务内完成；拒绝时只回传 `access_denied` 和原 `state`。
6. RP 回调验证 `state`、Cookie、事务期限和一次性状态，使用服务端客户端认证及 PKCE 换码。通过固定受信任平台地址读取发现文档、JWKS 和 userinfo。
7. RP 使用 Authlib 验证 RS256 签名、issuer、audience、nonce、有效期和 `at_hash`，并确认 ID Token 与 userinfo 的用户、企业、订阅和租户完全一致。租户必须已经由管理接口开通。
8. RP 建立独立 HttpOnly 会话，最长五分钟且不超过用户令牌期限。每次应用访问重新请求平台 userinfo：禁用用户、撤权、到期、租户关闭或安全下架立即拒绝。普通成员不会因获得 SaaS 访问权限而获得文件下载或 API 凭据权限。

当前浏览器绑定 Cookie 同一域名只支持一个进行中的授权事务；同时在多个标签页发起登录会使较早的事务失效，应重新从应用启动。平台既有登录 JWT 存储方式未在本批迁移；新增 OIDC 授权码、RP 访问令牌和客户端密钥均不写入浏览器本地存储。开发验证使用不同主机名隔离平台与 RP Cookie，不能仅依靠不同端口隔离 Cookie。

## 3. 数据与权限

平台 `oidc_browser_requests` 保存随机请求 ID、客户端、已验证的授权参数、浏览器 Cookie 哈希、到期时间、消费时间和操作用户。`oidc_authorization_codes` 保存授权码哈希及兑换、撤销状态，不保存明文授权码。

模拟 SaaS 私有 SQLite 保存客户端配置、租户、用户、部门、登录事务、身份映射和会话；文件权限 0600，并挂载 PVC。客户端密钥及访问令牌只保存在 RP 服务端，不发送到浏览器。测试管理接口默认关闭，开发环境显式启用后仍须独立管理密钥；不得用于生产开放管理。

应用访问范围按实际有效企业成员关系计算，支持用户加入多个企业。购买企业超级管理员、管理员可以访问有效订阅并管理普通成员授权；普通成员仅可访问明确获授的应用。提供方管理员不能因提供产品而管理购买方成员。平台角色账号不进入企业“我的应用”。管理员固有访问权不可通过普通成员授权接口撤销。

授权变更、应用启动、授权码签发、兑换和用户拒绝均写审计日志，不写 Secret、Token、授权码、state 或 nonce。成员授权记录产品、企业、目标用户和变更前后结果。

## 4. 应用接口

| 接口 | 功能 | 权限 |
| --- | --- | --- |
| `GET /api/applications` | 当前用户所有企业内可见 SaaS 应用，包含可用状态和不可用原因 | 已实名有效企业成员 |
| `POST /api/applications/{subscription_id}/launch` | 复核权限，返回应用启动地址 | 购买企业管理员或获授权成员 |
| `GET /api/applications/{subscription_id}/members` | 本企业有效已实名成员及授权状态 | 购买企业管理员 |
| `POST /api/applications/{subscription_id}/grants` | 使用 `user_id`、`granted` 授予或撤销访问 | 购买企业管理员 |
| `GET /api/oidc/browser/{request_id}` | 读取浏览器绑定授权确认信息 | 当前登录用户及绑定浏览器 |
| `POST /api/oidc/browser/{request_id}/approve` | 一次性确认授权并返回受信任回调地址 | 同上，且 Origin 正确 |
| `POST /api/oidc/browser/{request_id}/reject` | 一次性拒绝授权 | 同上，且 Origin 正确 |

以上响应使用 `Cache-Control: no-store`。失效请求需重新从应用发起，不沿用旧请求。回跳目标不接受任意外站登录返回地址。

## 5. 部署与验证

平台继续部署在 `market` 命名空间；签名密钥沿用现有 Kubernetes Secret，不因更新镜像而重新生成。模拟 SaaS 使用独立 PVC、管理 Secret 和 NodePort 30083，既有 APISIX 30082 保持不变。浏览器验收临时将本机 `127.0.0.1:30082` 转发至模拟服务；此 localhost 回调只用于开发测试，并非真实第三方生产访问地址。

生产必须使用 HTTPS、真实 RP 域名和精确回调白名单，关闭测试管理 API，并完成第三方环境联调。本次模拟链路不能替代第三方系统验收，也不表示全平台所有任务均已完成。

验收覆盖：登录回跳、同意与拒绝、独立 SaaS 会话、普通成员入口、管理员授权撤权、跨企业拒绝、失效订阅与禁用用户拒绝、PKCE/state/nonce/签名错误、一次性请求重放和桌面/移动布局。测试只使用带归属标识的隔离数据；清理 RP 状态后按精确 ID 清理 PostgreSQL 数据及审计、消息依赖，不操作真实产品与订单。

实际执行结果、截图、部署标签、测试计数和剩余限制另记于本批验证记录，未执行项目不得标记通过。

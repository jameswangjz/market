# 产品登记发布与交易履约功能需求说明

版本：v1.0；日期：2026-10-10。依据：用户本轮登记发布、交易、履约、续费升降级及清算确认。本文为新需求基线，不代表所述新能力已上线。

## 1. 范围和优先规则

覆盖产品登记、四阶段审核、接入验证发布、匿名商城、企业购买、支付、线上线下交付、订阅期限、企业共享API凭据、续费、三类服务版本升降级、清算经济调整、权限、审计与通知。
本轮规则优先于旧的API无期限次数包、订单额度叠加、SaaS新增多个独立租户及企业管理员可发起支付规则。历史已成交订单保留原合同，不直接强制改成新规则。
国家数据基础设施与接入连接器对外接口仍不在首版开发范围；真实支付渠道仍未接入，本专项以模拟支付和人工到账确认验证。
产品和交付类型不是同一维度，按所选交付方式决定订单和履约流程。不存在新增对象存储交付方式，MinIO仅为内部存储组件。

## 2. 功能分解与编号

以下36组功能需求对应开发任务JSON的42项工程任务。需求组数不等同实现功能点数量，一个需求组包含多个校验项。

### 2.1 登记与发布

| 编号 | 功能 | 规则及验收要求 |
|---|---|---|
| REQ-01 | 登记主体 | 提供方企业须已认证，操作者个人已实名且为企业超级管理员、管理员，登记编辑本企业产品；必须显式选择企业，服务端核查当前成员身份 |
| REQ-02 | 交付分类 | 线上：文件下载、API服务、模型API、租户/权限开通；线下：培训、咨询、定制开发；分类由方式派生，用户不能提交互相矛盾值 |
| REQ-03 | 产品Logo | 仅产品Logo，不使用企业Logo兜底。380×280，原图及缩略图持久化，病毒检测、SVG安全清洗；提交审核前必需，草稿允许分步上传 |
| REQ-04 | 版本与报价 | 每版本编号、简介、价格、成本和兼容性；三种月付交付方式按月价/月成本，文件及线下按单价格/成本；不得售价低于成本 |
| REQ-05 | 文件配置 | 文件绑定版本，zip/tar/rar/7z等已支持归档格式；10GB以下，流式上传；先ClamAV再Presidio，报告可查下载；每订单下载次数，0不限，已售文件不覆盖 |
| REQ-06 | API版本配置 | 每版本登记上游URL、路由标识、入口认证、上游认证、Scope、月配额千次单位、日限额、每分钟限流、超时、健康检查路径和GET/HEAD方法 |
| REQ-07 | SaaS配置 | 应用访问URL、管理接口URL、月价成本、版本兼容性、OIDC回调地址；机器OAuth接入凭据与人员SSO客户端独立管理 |
| REQ-08 | 四阶段审核 | 业务、质量、安全、运营流程及权限保持不变；原撤回/拒绝原因、文件报告及审核日志继续保留；不得从旧publish接口绕过审核 |
| REQ-09 | 接入验证发布 | API/模型API四审核后待接入验证，提供方获取接入信息完成配置；健康及网关配置一致后版本可售，失败不可购买；状态和错误可查、可重试 |

草稿/被驳回可编辑，待审核所有者仅撤回；已发布所有者/平台按原授权下架。手动下架不影响已售权益，安全策略下架按原安全回收策略执行。
新增版本或替换上游必须形成受审核的接入配置修订；不可修改已售版本的文件/价格成本快照。已有可售版本不因新增版本验证失败被无差别禁用。
一个产品至少有一个审核与接入均通过的有效版本才进入已发布可售状态，商城仅显示可售版本，不展示待接入版本。

### 2.2 公开商城及订阅支付

| 编号 | 功能 | 规则及验收要求 |
|---|---|---|
| REQ-10 | 双入口 | /公开商城，/console登录后台；后台沿用现有界面风格和模块，菜单及动作按角色限制，直接URL及F5均有效 |
| REQ-11 | 商品列表 | 每个商品区域显示产品Logo、名称、真实提供方企业名称、最低可售版本价格；月付显示元/月，一次性显示元/单；支持搜索分类分页及加载空错误状态 |
| REQ-12 | 商品详情 | 点击Logo/名称进入独立详情页，展示公开元数据、版本简介、价格、交付方式、配额及相关对接文档；不展示成本、上游URL、Secret、内部规则及审核日志 |
| REQ-13 | 订阅资格 | 未登录、未实名及未认证企业可浏览不可订阅；仅已实名用户且为已认证买方企业super/admin可订阅，必须选择购买企业 |
| REQ-14 | 购买参数 | API、模型API、SaaS月数为整数1..36；文件及线下一次性无月数；金额与成本均保存版本月单价乘月数，币种CNY、精确到分 |
| REQ-15 | 在线订单 | 生成后直接待支付，不需要提供方订单审核；付款与到账确认后自动启动交付；交付成功才开始服务期限 |
| REQ-16 | 线下订单报价 | 生成后待提供方审核，可调整本单金额成本且金额>=成本，必须记录原因和原值新值；批准待支付，拒绝必填原因并结束订单 |
| REQ-17 | 支付角色 | 仅买方企业超级管理员发起支付；企业管理员可订阅/取消未付款订单及验收，不可支付；平台财务清算人员保留人工到账确认，不冒充买方身份 |
| REQ-18 | 成本保密 | 买方列表、详情、响应、导出、报价、消息、审计摘要均不可见成本及利润；只有提供方本企业授权管理人及有权限的平台财务/审计人员可查看相应范围 |

付款前买方查看最终报价；提供方审核批准后报价冻结，不能与付款并发更改。付款后不得改成交金额或成本，仅允许有记录的退款或经济调整，不篡改原单。
订阅和支付分别鉴权，不因下单人曾是管理员而永久保留权限。用户禁用、离职、降权后按当前身份判断；后台隐藏按钮不能替代服务端校验。

### 2.3 交付与访问

| 编号 | 功能 | 规则及验收要求 |
|---|---|---|
| REQ-19 | 文件线上完成 | 文件已持久化且扫描通过，买方订单下载授权已创建、入口可用才完成；链接存在不等于有权下载 |
| REQ-20 | API线上完成 | 上游健康、APISIX路由、认证及有效权益均一致后完成，提供网关地址及调用方接入信息；不能把未同步的Key当成功交付 |
| REQ-21 | SaaS线上完成 | 第三方开通原租户及管理员、平台保存租户标识和权限映射、应用访问入口验证后完成；不要求买方再验收 |
| REQ-22 | 交付异常 | 首次失败后间隔10秒最多自动重试3次，明确尝试次数和最后错误；仍失败进入交付异常待人工，保留已支付订单，不虚报完成或自动冒充退款到账 |
| REQ-23 | 订单访问列 | 订单列表第二列“应用访问地址”：文件下载、API/模型接入信息、SaaS进入应用；未交付/过期/被回收显示不可用原因，Secret不直接在列表或URL中出现 |
| REQ-24 | 文件及凭据权限 | 买方仅super/admin可下载产品文件、取得/停用/重生成API调用方凭据；普通企业成员禁止，即使本人曾经下单；审核人员仅授权审核范围下载 |
| REQ-25 | SaaS用户SSO | OIDC授权码+PKCE，已获该应用访问授权的普通成员可SSO；按企业、租户、应用及用户映射判断，不因此获得文件/API凭据权限 |
| REQ-26 | 线下履约 | 已付→待开始履约→提供方确认开工→履约中→提供方提交→待买方验收→买方通过→履约完成；拒绝进入履约整改，再提交回待验收 |

线下提供方super/admin开工、提交交付及整改；买方super/admin验收通过或拒绝，拒绝原因必填。联系人、交付说明、计划完成时间、实际完成时间及验收附件持续保留。
履约完成与服务仍有效是不同状态：API/SaaS成功开通即可完成履约，后续到期影响服务权益，不把原历史交付完成改成未完成。
平台审核人员下载不消耗买方订单次数；买方下载受每订单次数限制并记录用户、时间、结果，普通成员不能借公开文件链接绕过授权。

### 2.4 订阅、续费及配额

| 编号 | 功能 | 规则及验收要求 |
|---|---|---|
| REQ-27 | 日历期限 | 从交付成功时刻开始；原始日期对应目标月份，无该日期取月末，保留原始锚点避免逐月漂移；业务时区Asia/Shanghai、数据库UTC |
| REQ-28 | 多订单续费 | 企业+API产品共享凭据，同版订单只顺延有效期，不叠加当前限额或配额；有效订阅接期，已到期恢复交付成功后重起；未来已付时段不提前生效 |
| REQ-29 | 订阅月预算 | 月配额输入值乘1000，0不限；按服务锚点划分订阅月，日限额按北京时间自然日，每分钟限流保留；无有效权益不是“无限” |
| REQ-30 | SaaS组合 | 首购可创建企业+产品组合；后续仅现组合续费/升降级，不新增独立租户；旧多实例保留并显式选择目标，不删除合并 |

日期例：1/31→2/28→3/31；1/30→2/28→3/30；2/28→3/28。原始日期恰为月底不自动启用“始终月底”规则。
期限半开区间[start,end)，到end时刻不再有效。每次购买1..36个月，续费可延长组合总期限，不将36个月误当所有历史累计期限上限。
同版本续费不中途重置当前月/日已用量；API凭据重生成也不能清零余额。不同版本购买引导升降级，不同时叠加互相冲突的版本权益。
SaaS单纯到期且租户仍存在可恢复续费；已关闭租户按既有至少1个月保留及恢复边界核验，超出保障不承诺可恢复，也不默默创建新租户。

### 2.5 升降级和清算

| 编号 | 功能 | 规则及验收要求 |
|---|---|---|
| REQ-31 | 三类版本切换 | API、模型API和SaaS均可变更；展示接口兼容性及需用户修改配置的风险，切换前确认；共享服务当前及已购买未来时段一并报价 |
| REQ-32 | 剩余比例报价 | 对每个来源订单完整购买时段取剩余秒数比例；原实际成交收入/成本冲回，目标月价/月成本乘该订单原月数后按同一比例计入，净差额只支付或退款一次 |
| REQ-33 | 生效与恢复 | 升级支付成功并第三方/网关变更成功后生效；降级资源回收与退款关联，不退款成功仍保留高权限；失败有可恢复台账、重试补偿和人工处理 |
| REQ-34 | 用量连续 | 周期内版本切换保留已用量，新额度减已用量得余量；降级已用量超过新额度则暂停至下周期，退款/到期只回收对应有效时段 |
| REQ-35 | 正负经济清算 | 旧剩余收入成本按旧规则形成负向，目标剩余按目标确认规则形成正向并冻结快照；只算一次，不把净差价订单再扣完整目标成本或重复产生退款负单 |
| REQ-36 | 审计及通知 | 登记审核接入、报价改动、支付确认、履约验收、续费变更、授权回收和清算调整记录操作者/对象/时间/结果/前后值/request_id，阶段事件按既有消息中心发出 |

原单及已使用部分不变。连续升降级以当前有效经济基线的未使用部分为依据，不每次再次冲回最初原单。
经济计价合同段与QuotaPeriod不同：月度预算用于调用额度，不把各订阅月平均收入另作分母替代用户的“原订单剩余/原订单完整时长”公式。
净差价为0但成本或规则变化，仍须生成正负经济调整；合法版本之间产生负的净利润调整按有符号值记录，不强行截成0。
普通退款沿用退款完成负清算；已关联升降级经济调整的净退款不能再次按通用路径冲回同一经济金额。新调整按成功生效时刻归属自然月，保留实际到账/退款时间，报表区分经济调整和真实资金流水。

## 3. 状态和权限摘要

线上订单：待支付→已支付/交付中→履约完成；交付失败→重试→异常待人工。支付、交付、服务权益分别记录，不能压成单一状态。
线下订单：待提供方审核→待支付→待开始履约→履约中→待买方验收→履约完成；拒审结束订单，拒验进入整改再提交。
产品审核：草稿→业务→质量→安全→运营；拒绝保留原因，撤回回草稿；API通过后待接入验证→可售发布。
变更：报价→待支付/待变更→资源变更中→待退款（降级）→成功，失败可重试/补偿/人工处理；成功后原经济段标替代，新段有效，历史分录不覆盖。

| 角色 | 允许范围 |
|---|---|
| 匿名/未实名 | 公开商城及详情，不订阅、不给文件/API或后台敏感信息 |
| 买方普通成员 | 浏览及已获授权SaaS的SSO，不付款、不文件下载、不API凭据 |
| 买方管理员 | 订阅、续费/变更申请、取消未付、线下验收、文件/API授权管理；不能发起支付 |
| 买方超级管理员 | 管理员权益加发起支付；每次以当前企业角色鉴权 |
| 提供方super/admin | 本企业登记和撤回、审核线下订单改报价成本、开工/交付/整改、下载提供方接入配置 |
| 平台四审核角色 | 按既有阶段审核、查看资料和报告；不自动拥有买方凭据或买方支付身份 |
| 财务清算 | 平台授权范围到账确认、清算及经济调整查看；不能创建虚假的买方身份 |

## 4. 非功能与验收要求

所有状态变更幂等、同组合并发受锁及唯一约束保护；事务失败不留下半订单、半权益或孤立清算记录。外部资源调用与资金采用可恢复Saga，不宣称跨系统单事务。
上游URL及健康检查执行SSRF防护、白名单和超时；OIDC回调精确白名单，生产HTTPS；凭据加密保存，日志/导出脱敏，访问凭据与提供方机器凭据分离。
继续本地ClamAV和Presidio，不把Presidio当杀毒引擎；报告查看下载和审核日志原能力回归。月配额变更需验证真实Redis与APISIX，不以接口返回200代替数据面成功。
界面延续现有风格，商品展示使用实际Logo；桌面移动页面、订单第二列和弹框不溢出；公开入口可直接访问与刷新，后台权限不因公开商城出现而放宽。
新功能逐项通过验收矩阵后更新任务状态。本轮设计、任务导入及巡检不等于商城、OIDC或新升降级已经开发完成。

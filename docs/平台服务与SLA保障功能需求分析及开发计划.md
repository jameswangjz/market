# 平台服务与 SLA 保障功能需求分析及开发计划

## 1. 建设目标

本模块对应招标要求“13.5.3.2.4.6 平台服务与 SLA 保障功能要求”，将现有 API 网关监控、交付截止时间和审计能力统一纳入平台服务等级管理，形成“规则定义、服务绑定、指标采集、周期考核、预警违约、审计追踪”的闭环。

首期采用平台内部可验证的指标口径，不依赖外部监控产品才能使用；Prometheus/Alertmanager 继续承担基础设施和 APISIX 告警，SLA 模块负责面向平台运营和服务验收的业务结果。

## 2. 功能范围

### 2.1 服务级别与支持权益

平台内置并允许调整标准级、企业级和战略级服务级别。服务级别采用配置化方式维护支持周期、首次响应时长、问题响应时长和支持权益：标准级默认 5×8、48 小时问题响应；企业级默认 7×8、24 小时问题响应并提供专属技术支持经理；战略级默认 7×24、15 分钟紧急响应，并提供季度服务报告和年度服务优化建议。平台管理员可创建自定义级别，并将级别绑定企业；绑定级别会在售后工单创建时生成对应响应截止时间。

### 2.2 SLA 规则管理

- 规则名称、服务范围和说明；
- 服务范围支持平台服务、API 服务、交付服务和指定产品；
- 可用性目标、平均响应时间目标、错误率上限；
- 交付时限、故障恢复目标和预警裕量；
- 启用/停用、创建人、创建时间和变更审计；
- 后续可扩展按租户、合同、产品版本和服务等级模板绑定。

### 2.3 指标采集与计算

- API 服务读取 `ApiUsage` 和网关路由数据；
- 可用性 = 成功请求数 / 总请求数；
- 错误率 = HTTP 状态码大于等于 400 的请求数 / 总请求数；
- 平均延迟从网关调用记录计算；
- 交付及时率根据交付任务状态和 `sla_due_at` 计算；
- 暂无样本时按 100% 记录，同时保留样本数，避免把“没有流量”误判为故障；
- 支持手动触发考核，后续由定时任务按小时/日/月执行。

### 2.4 结果和处置

- 结果状态：达标、预警、违约；
- 记录考核周期、样本量、成功量、可用性、延迟、错误率、交付及时率和违约原因；
- 违约和规则变更写入审计日志；
- 后续扩展告警通知、事件单、维护窗口、升级响应、服务补偿和 SLA 报告导出。

## 3. 接口边界

- `GET /api/sla/overview`：规则、统计摘要和最近考核结果；
- `POST /api/sla/profiles`：创建 SLA 规则；
- `PATCH /api/sla/profiles/{id}`：编辑或启停规则；
- `POST /api/sla/evaluate`：执行当前周期考核；
- `GET /api/sla/results`：查询历史考核结果。

以上接口仅允许系统管理员和平台运营人员使用。所有创建、修改、启停和考核动作写入 `AuditLog` 的 `sla` 分类。

## 4. 数据模型

- `sla_profiles`：规则及阈值；
- `sla_results`：按规则和考核周期保存不可覆盖的考核结果；
- `service_levels`：服务级别、支持时段、响应时长和权益；
- `service_level_assignments`：企业/用户服务级别绑定及有效期；
- 现有 `api_usage`、`api_gateway_routes`、`delivery_tasks` 作为指标来源；
- `after_sales_tickets` 保存命中的服务级别和响应截止时间；
- 现有 `audit_logs` 作为规则和结果变更的审计来源。

## 6. 后续增强计划

后续迭代应增加 Prometheus 查询适配、自动定时考核、通知渠道、服务事件和维护窗口、SLA 报告导出、按租户/产品版本绑定、违约补偿以及月度合同结算。当前首期已经具备平台 SLA 管理的基础闭环，不把架构图中的能力描述误认为已实现功能。

# R3多资金来源退款设计补充

## 已确认规则

适用于已升降级的订阅再次发起普通退款。优先退最近到账的升级补款，再退较早到账的支付；每个来源按原支付渠道退款。每笔可用金额为实付减去已完成退款及其他在途冻结金额，不能跨企业、跨币种或超出来源余额。金额精确到分，不用浮点数分配。

退款资金排序与收入成本冲回是两个不同维度。收入、成本及五方分成仍使用退款涉及的原经济段快照；不因优先退升级补款，就把全部退款按最新版本利润或规则计算。

## 服务端关联与边界

1. 由原订单、其有效订阅段、已完成版本变更及VersionChangeFund关联到已确认Payment。来源清单不能由前端任意提交。
2. 未完成、失败补偿或被作废的版本变更不能提供可退款资金。已完成降级退款须扣除，不因本次普通退款重复返还。
3. 来源排序以实际到账时间降序；时间相同按稳定payment_id排序，保证重试一致。付款时间缺失不得猜测先后。
4. 一个退款申请需关联多条支付来源分配记录，不能把原Refund.payment_id单一字段冒充全部原路退款计划；保留该字段的历史兼容语义。
5. 审核冻结时校验并冻结每笔资金来源和金额；金额合计必须等于批准金额。资金不足整体拒绝，不暗中截断用户申请。
6. 执行时逐来源幂等台账，只有资源回收与全部资金步骤完成，才能标记整个退款完成。模拟退款不能标为已验证银行到账。

## 开发边界

BE-011先实现纯资金分配器和严格输入校验，再接入服务端资金关联、来源占用与跨经济段快照。纯函数不负责身份鉴权、DB锁、资源回收或利润计算；不能把纯函数通过当作整个多来源功能完成。

BE-012在已冻结方案上执行，处理并发变化、资金/资源失败、重试和重启恢复。FE-008显示申请/分配/执行结果，不暴露敏感支付或提供方凭证。QA-005验证多来源累计不超退、在途占用、幂等及故障恢复；退款完成后才交由BE-013产生清算负向调整。

## 依赖顺序

按用户最新确认：BE-011完成后启动BE-012，随后收尾FE-008与QA-005。已完成的BE-010保留待验收，不倒退为待开发，也不代用户验收。

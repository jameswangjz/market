# 企业工作台与产品运营调整需求说明

## 1. 生效范围和优先级

本说明依据本轮14项问题及后续确认，覆盖历史需求中冲突的规则。保留此前已确认的模拟支付、每版本成本、利润清算、升降级双腿调整、企业共享API凭据、订阅月及北京时间自然日限额。代码开发采用用户确认的 gpt-6-luna medium，需求、代码审查与功能验证由主Agent当前模型完成。任务代码 TRD-R2-*；任务清单共20项。

## 2. 新旧规则冲突处理

| 历史或现有行为 | 本次有效规则 | 历史兼容 |
|---|---|---|
| 后台未实名用户可列举全部已发布产品 | 企业后台仅当前企业提供的产品，公开浏览走商城 | 不向后台返回其他企业内部元数据 |
| 默认首个企业决定列表权限 | 使用显式当前企业，并验证活跃成员关系 | 多企业账号必须可切换 |
| 模型可默认模型API，报告/应用交付可选 | 新登记模型、数据报告、数据应用均文件下载 | 已售订单仍执行冻结快照；已有模型API不直接改为文件 |
| 运营审核时API可能立即发布 | SaaS/API/模型API统一先待接入验证，接入成功发布 | 不增加业务审核环节 |
| 健康失败直接影响可购买资格 | 发布后的健康异常只记录和通知，不影响新购 | 安全下架仍影响授权及购买 |
| 手工关闭/恢复租户 | 取消订单页两个按钮 | 后端生命周期接口保留，不自动给企业管理员增加其它权限 |
| 手工路由标识 | 网关生成稳定路由标识 | 已发布路由/已售链接保持身份 |
| API版本兼容性及兼容期 | 提供方、购买方统一使用最新调用规范，不要求旧调用方式兼容 | 不自动改变已购版本的价格、期限、配额或授权路由 |
| 固定目录字符串 | 持久两级目录，产品关联二级目录ID | 原字符串按明确映射迁移，无法映射需修正，不静默归类 |
| 右上角角色写死平台管理员 | 按平台角色/当前企业成员角色显示 | 同用户切企业时角色同步变更 |
| 企业总览混合采购/销售 | 仅企业超级管理员查看本企业提供方经营指标 | 平台统计与企业统计分开 |
| 原需求箭头方向 | 左平台右SaaS，右同步左移除 | 双箭头全部，均需确认范围 |

产品类型目前没有独立模型API类型。因此本轮新登记模型绑定文件下载；历史模型API能力保留。如未来需要新登记模型API，应新增显式模型API产品子类型并单独确认，而非绕过映射规则。

## 3. 企业身份、角色和控制台

企业作为租户，一个用户可加入多个企业和多个部门。每次后台业务请求指定当前企业，服务端检查成员活跃、用户活跃/实名及操作角色。平台账号不挂企业。

企业超级管理员、管理员可登记/编辑本企业产品；普通成员不能执行这些操作。后台任何企业角色不能读取其它企业的内部产品、版本成本、报告或提供方凭据。普通成员菜单只展示其授权功能。公网商城只提供公开字段。

控制台分为提供方和消费方视角，共用当前企业选择。提供方包含运营总览、数据与服务、销售订单、履约与售后、其参与的清算、销售相关审计和消息。消费方包含我的应用、采购订单、采购履约与售后、采购相关审计和消息。用户与企业、个人设置是公共区域。平台内部账号使用平台工作台，不套企业角色。

运营总览仅企业超级管理员可见。产品数按本企业已发布产品；订单和完成量按本企业提供方订单；累计确认收入按确认付款收入，并单列已退款及净收入。接口与导出一致限定范围。

## 4. 登记、目录和接入

新登记类型交付映射：dataset/model/report/application -> file；api -> api；saas -> tenant_access；training -> training；consulting -> consulting；custom -> custom。产品Logo必填；文件绑定版本、扫描报告和下载限制沿用原要求。

配额标签合并说明：每日配额（次，0表示不限）；每订阅月配额（千次，1千次=1000次，0表示不限）。录入千次，内部统一保存次数。API与模型API价格/成本仍为每月，续费不叠加当前额度。

API提供方填写版本上游URL、上游OAuth Scope、超时、健康路径/方法和配额。入口认证是调用方到网关；上游认证是网关到提供方，采用平台OAuth。路由标识自动生成、只读展示。移除路径前缀控制网关转发路径，不等于上游访问路由。取消API版本兼容性输入和旧调用方兼容期要求；提供方资源服务与购买方调用代码统一按最新指导文档适配。调用协议变更须更新文档并通知相关方，不能因此自动更改已购买版本、收费和期限。

HTTP支持由系统地址策略统一控制，覆盖应用入口、上游、管理接口、健康探测及OIDC回调；允许HTTP不关闭URL校验、SSRF防护和回调精确匹配。

四阶段审核保持原权限和审计。运营审核通过后，接口类产品待接入验证，提供方可下载OAuth/OIDC接入信息、配置服务、手工立即验证。后台5分钟自动复查已具备配置的待接入产品。配置、凭据、健康和发布证据全部满足后进入已发布。SaaS还需有效OIDC客户端/回调及可调用管理接口契约；不使用真实企业创建测试租户。

商城不显示原因在有权限的后台展示，例如待接入、无有效版本、版本价格非法、配置缺失、路由证据缺失。已发布且有效产品展示，不因发布后健康检查失败隐藏。健康异常与产品发布、安全状态分开。

产品目录只有两层。平台管理员和运营维护；一级可含多个二级，产品必须挂二级。含子目录的一级不能直接删除；有关联产品（任何状态）的二级不能删除，软删除产品的保留关联按规则处理。显示一级目录 · 二级目录。商城两行目录选项筛选，选择一级时清空不匹配二级；交付方式替换旧全部类型筛选，搜索框缩窄且移动端可换行。

## 5. 健康检查和服务质量

默认每300秒检查一次；连续失败3次标服务异常，第一次达到阈值通知提供方管理员及平台运营；后续同一异常不重复通知。一次成功归零连续失败、恢复健康，记录恢复时间。失败包含网络异常、超时、非约定成功码及必要认证失败。探测记录目标版本、工具/协议、时间、状态码、耗时和脱敏错误。

异常不暂停新购、不自动下架。购买后仍须通过真实交付证明才能履约完成，交付失败沿用10秒三次重试及人工处理。安全策略另行安全下架。探测可用率、响应时延用于SLA；5分钟采样估计可用性，不宣称精确请求级可用率。

## 6. 订单和SaaS用户部门管理

确认支付成功立即更新列表和详情，以服务端返回为准；异步交付继续刷新，订单切换/请求乱序不能把状态回退。财务人工确认和买方超级管理员支付保留。

新线上订单待支付 -> 交付中 -> 已完成；失败有交付异常并转人工。新线下订单待提供方审核 -> 待支付 -> 待开始履约 -> 履约中 -> 待买方验收 -> 已完成；拒绝验收 -> 履约整改 -> 再次待买方验收。拒绝订单需原因。主状态、支付、履约、售后分别显示；历史状态只读兼容，禁止旧动作绕过新流程。

SaaS取消订单页关闭/恢复租户。用户管理和部门管理仅对购买企业超级管理员/管理员可见，后端同步接口同权。左树平台企业，右树该订阅SaaS已同步对象；单右箭头同步选中，双右全部；单左移除选中，双左全部。用户多部门关系同步，部门按父先子后创建，移除按子先父后。只有平台活跃成员可同步，操作检查订阅有效。部分失败可重试且展示逐项状态；移除右树对象不删除左树成员或部门。第三方调用、前后映射及审计持久化。

每个任务必须关联代码、测试结果和部署版本；功能开发中不因等待时间卡死自动重启。测试未覆盖时保持进行中，完整开发验证后待用户验收。使用专属夹具和精确清理，保留ORD-261012005144E1B3及依赖产品。真实银行及外部真实供应商联调单列。模型工具不提供Token用量时记录未知，不估算成实测。

# 订单类型与订阅履约状态需求及设计

生成时间：2026-10-19 16:53:23（北京时间）。本次确认替代此前买方自行确认模拟到账、线上订阅开通即订单完成的规则。

## 需求基线

1. 订单类型：新购、续费、升级、降级、退费。内部经济用途business_type不与展示类型混用。
2. 确认升级立即创建待支付升级订单、支付单及幂等资金关联；发起支付只推进状态，不延迟创建订单。同一幂等请求返回同一订单。
3. 升级覆盖当前剩余时段与全部已购未来续费时段，逐段关联原订单。订单开始时间为新订单创建时间，截止为涉及各段的最晚截止；不额外延长期限。资源实际切换时间单独保存，不把未付款订单当作已切换。
4. 仅买方企业超级管理员发起支付。任何买方、企业管理员、普通成员及财务清算角色均不能确认到账；仅激活且已实名的平台系统管理员、平台运营人员可以人工确认支付。接口和页面均执行同一权限。
5. 订单保存成交版本与服务开始、结束、实际生效时间。原订单的成交版本不被新版本覆盖。文件产品无订阅截止，尚未交付的新购订阅起止时间不可伪造。
6. 已支付未来续费：主状态待履约、支付已支付、交付待生效。到达开始时间，进行实际可达性及资源检查；通过后主状态履约中、交付验收通过；失败为待履约、交付异常。10秒间隔最多三次后转人工。服务截止后主状态已完成，保留真实支付和交付结果。
7. 新购订阅通过开通验证后进入履约中，不等到用户手工验收；文件、线下服务的既有完成标准不变。租户及API共享凭据不因到达新订单期间而重复开通或重置用量。
8. 降级订单金额为负向净差额；退费订单为关联原订单及退款记录的负向现金记录，不新增正向Payment，不重复启动交付。

## 数据与处理设计

- orders新增order_type、service_starts_at、service_ends_at、service_effective_at；字段可空，明确区分未确定与无期限。内部升级资金单business_type保留原值，避免破坏既有经济段清算过滤。
- order_service_states独立持久化生效任务、下次时间、尝试次数及安全错误摘要。复用在线交付工作进程，不依赖浏览器刷新触发状态。
- 未来续费先完成提供方权益配置及期限登记，但未生效时API网关不开放对应时段。生效检查意图先提交，再幂等同步网关与状态；不重新生成期限、叠加配额或重置计数。
- 人工重试仅平台交付操作角色可执行，留下审计；不能将已过期订单重新激活。
- refund_order_links以refund_id唯一关联负向现金订单。仅新建或修改退款记录时同步，不扫描历史退款自动补造；冻结购买方、提供方、版本与服务期。拒绝、待处理、完成分别展示，完成前不视为已退资金。
- 资源切换成功后，升级/降级操作订单单独记录实际生效时间，沿用冻结的截止时间，不改写原支付和退款上限。

## 清算不变量

- 普通收入仍按支付确认月份入批；已支付待履约续费不得因未完成服务而被排除。
- 降级和退费现金方向均为负，但不是把所有关联经济行强行改为负。版本切换继续采用原版本剩余收入/成本负向冲回、目标版本剩余收入/成本正向计入，净额对应补收/退款。
- 降级操作订单及退费现金订单不再作为一笔额外收入/退款直接重复生成经济清算；原版本变更台账、退款清算调整单仍是经济入账来源。
- 服务开始或结束只记录履约状态，不重复收款、不再次生成收入清算。退款仍按已批准的最终清算基线及成本例外处理，资金追回独立跟踪。
- 续费交付SLA从冻结的服务开始时间与支付时间较晚者计时，避免提前付款订单在尚未开始服务时被判逾期；既有冻结承诺不追溯改写。

## 安全与兼容边界

- 旧版SaaS直接开通、续费及变更接口存在隐式完成付款或正向记录降级金额的旁路，统一拒绝执行，指引使用订单流程；不能因旧接口仍存在而允许买方确认到账。
- 网关策略发布复用既有数据库根事务回滚补偿；生效阶段若SLA或审计写入失败，立即恢复策略元数据，保留使用量计数，不把数据库回滚当作外部策略也已回滚。
- 生效第二阶段再次检查可达性及产品/租户状态，不能沿用第一阶段之后已经失效的验证结果。
- 缺少可信退款权益证据、证据明确拒绝访问或返回空权益时，不保持“履约中”；转异常核验，最多三次后转人工。新的退款状态更新不能绕过人工重试重新激活服务；全额退款只允许停止服务。
- 交付任务将资源配置完成但未来生效的订单记为“待生效”，真正生效后才记任务完成。旧交付重试入口不能再次为这类订单续费或开通。

## 验证与迁移

先进行权限、订单创建、退款镜像、状态时钟等小范围测试；合并后进行一轮订阅/版本/退款/清算组合回归，再部署并核验版本及前端实际下载。不能用单一接口成功替代完整浏览器交易结论。

必须覆盖：升级确认即见订单；重复请求不重复创建；买方/财务直接调用确认接口403；平台管理员/运营可确认；未来续费不提前开放；到期生效成功、失败重试、服务到期；跨版本与未来多段截止；退费无正向支付；清算不按订单完成过滤且无重复计入。

不批量改写历史金额、版本、用量或冻结SLA。历史订单类型与期限应基于可核实的原业务类型、订阅Term及变更关联进行单独盘点，缺乏证据时保留未知，不冒充新成交事实。受保护订单ORD-261012005144E1B3不得删除。

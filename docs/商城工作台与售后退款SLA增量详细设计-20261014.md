# 商城工作台与售后退款SLA增量详细设计
版本：v3.0；日期：2026-10-14；依据《运营平台新版功能需求说明-20261014》。
## 1. 当前实现与改造边界
已核对frontend/src/ConsoleApp.vue、productRegistration.js、backend/app/main.py、trading_policy.py、settlement_metering.py。
现有产品映射仍含report/application；售后submit_after_sales生成简化AfterSalesTicket并直接保存response_due_at；GET /api/after-sales返回简化工单；approve_refund创建退款，complete_refund直接完成并生成负清算且可能直接解决售后。ServiceLevel及ServiceLevelAssignment已有级别、时段、首次响应、企业绑定。应复用并扩展，不建另一套平行级别或重复负清算。
本设计的接口与表为拟议契约，除明确指出现有接口外不能当成已上线API。先抽取售后、退款、SLA服务模块并保留既有install(ns)及事务模式，避免扩大main.py。旧动作改为调用新服务/拒绝旧越权入口，不能保留后门。
## 2. 前端及公开查询
商城独立目录行+名称输入+产品类型选择；Query为q/category_id/parent_category_id/product_type/page/page_size，过滤逻辑AND。目录ID不合法400，二级不属于所选一级400；全部不传ID；总数来自同条件COUNT。新类型枚举dataset/model/api/saas/training/consulting/custom。旧类型不出现在新建/筛选可选集，迁移前历史详情标“历史类型”并保留原始值。
通用Pagination仅展示和事件，不直接决定数据权限。契约items,total,page,page_size；page>=1，界面提供10/20/50/100；服务端保持既有1..100范围以兼容旧12条请求，超范围校验；空列表显示0条无可跳页；排序使用created_at+id保证稳定。已存在分页的范围：商城列表、消息列表、审计列表、审计时间线及账单报告本地明细。逐页盘点其他列表，但不强行将无分页列表改成分页。账单明细保持客户端切片并如实标注，不能宣称服务端分页。过量请求限制及COUNT索引回归。
编辑弹框屏蔽遮罩/ESC，显式关闭调用dirty-check；保存成功重置dirty，失败保持；请求中保存和关闭禁止重复。仅用户确认可丢弃修改，无本地存储身份证/Secret。产品类型变化自动重置到固定交付并提示将清除不适用字段，后端拒绝伪造映射。现有已售版本保护不放宽。
开发进度用统一can_manage_development谓词，仅super_admin；覆盖菜单、总览、列表、详情、修改、导出、SSE及后台任务控制。个人未实名浏览及用户企业菜单权限不回归。业务身份控件局部CSS紧凑，不全局缩放所有字体。
## 3. SaaS我的应用
实现路径复核：仓库已有backend/app/applications.py及/api/applications、/{subscription_id}/launch、/members、/grants。应复用这些现有入口，以下拟议/my-applications名称不另建重复服务；列表增加enterprise_id显式选择，并验证活跃成员身份。现有available/blocked_reason响应兼容，扩展不得向买方暴露Secret。新旧契约映射及最终测试以R3执行证据为准。
GET /api/my-applications?enterprise_id&page&page_size：按用户实际活跃成员关系、SaaS授权、有效组合/租户查询，不能从buyer_user_id唯一推导授权。返回application_id/product_name/logo/access_state/entry_action，不返回客户端Secret、成本、上游管理地址。有效授权的普通成员可列举；过期/停用可返回不可访问原因但不返回可用登录链接。
POST /api/my-applications/{id}/launch：重查用户、企业、授权、订阅、OIDC回调，创建一次性短期登录桥接，精确绑定企业租户和PKCE/state/nonce；服务端不能相信前端enterprise_id。订单拥有者和授权成员两入口共用launch策略。授权撤销、成员禁用退出和到期复查授权；模拟SaaS会话也检查映射状态，真实供应商会话撤销能力单列边界。

## 5. 权限和工单状态机
每个操作必须当前角色有效、属于订单一方且企业明确；同企业兼买卖也按订单买卖身份校验，不使用菜单视角作为唯一授权。
| 动作 | 允许角色 | 起始→目标 |
|---|---|---|
| create | 买方super/admin | 无→awaiting_response |
| respond | 提供方super/admin | awaiting_response→processing；有效业务回复才停止首次响应时钟 |
| request_info | 提供方super/admin | processing→awaiting_buyer_info |
| supplement | 买方super/admin | awaiting_buyer_info→processing |
| submit_resolution | 提供方super/admin | processing→awaiting_buyer_confirmation |
| confirm/reject_resolution | 买方super/admin | awaiting_buyer_confirmation→completed/processing |
| withdraw | 买方super/admin | 非终态→withdrawn，已执行退款不撤回资金记录 |
| request_intervention | 买卖双方super/admin | 非终态→platform_intervention，保存原阶段 |
| review_intervention | 系统管理员/运营/交付监控 | 增加审查记录；返回合法处理阶段，不伪造买方确认 |
| force_close | 系统管理员/运营，交付监控无权 | 非终态→force_closed，原因必填，记录非验收关闭 |
评论不是任何角色都能执行状态动作；平台回复不算提供方业务响应。completed/withdrawn/force_closed终态禁止修改处理结果，仅可追加允许的审计评论；新问题创建新单，不重写旧证据。一单多个历史工单可保留，首期同订单同类别最多一条活跃工单，以DB约束/锁校验防重复。
## 6. 拟议售后与SLA接口
GET/POST /api/after-sales；GET /api/after-sales/{id}；POST /api/after-sales/{id}/actions。
动作体action,reason,expected_version,idempotency_key,attachments；状态不匹配/并发409、无权403、越权对象按现有404策略、参数422。事务内更新ticket+event+clock+audit+outbox，提交后通知。响应只含调用方可见字段，买方无成本。
GET /api/after-sales/{id}/timeline、/sla，GET /api/after-sales/export 按同权限过滤。事件可按工单、订单、企业、动作、人员、日期搜索。
复用/admin/service-level-assignments设计企业级别调整接口，实名审核表单可同时提交等级；认证批准及绑定同本地事务，拒绝实名不得生效SLA。已认证企业详情独立“调整SLA”，仅系统管理员/运营，填原因。平台指标配置与企业等级指派区分权限。
## 7. SLA时间与评估
补充确认：平台介入审查不创建pause区间；支持日历外不累计与业务暂停区分。线下交付订单排除线上交付及时率，其售后工单正常创建各责任方时钟。《SLA在线指标采集与统计口径确认稿-20261014》已接受，为采集、样本、错误排除、归责和deadline归月的冻结契约；增加不足样本/无数据源结果，禁止默认100%达标。
最新确认：业务时限输入及API配置契约统一为分钟，内部换算为秒，支持小数分钟（3.2分钟=192秒）；支持天数和每日支持小时不转换。最终矩阵普通解决4320/2160/1080分钟，整改1440/720/360分钟，战略紧急响应360分钟。旧problem_response_hours不得直接写分钟数，需显式换算或单位化配置，保留旧快照原单位。以提前预警修正版矩阵为准，不代表开发环境旧15分钟配置已修改。
支持日历快照包含业务时区Asia/Shanghai、周工作日、每日支持窗口、节假日版本；原仅每周天数/每日小时不足以确定起止，新增明确窗口，不能默认为任意8小时。全天指标按真实经过秒，工作时指标只积累窗口内秒。
创建时冻结三个责任方的指标定义。首次响应：创建→提供方首个有效业务回复，不暂停；解决：创建→买方确认/强制关闭，减等待补充及等待验收区间，强制关闭统计单列，不等同正常解决。平台介入指标独立从申请时开始。重开处理累计前段，不重置承诺。
单调事件和UTC时间计算，区间不交叉且不重复扣减；低于阈值为正常，等于/超过按明确阈值判断，不出现可用率100%因高于99.9%而预警。定时评估仅标记/发通知，不改工单业务状态。超时事件唯一键工单+指标+阈值阶段，Redis广播仅提醒，PG为事实源。
测试日历月末、闰年、夜间、跨周、节假日、暂停恢复、并发、规则调整快照不追溯。报告包含样本不足/历史缺证，不将缺证视为达标。
## 8. 退款流程与接口
POST /api/orders/{order_id}/refund-requests：买方super/admin提交原因、金额、ticket可选、证据、幂等键；创建REF待审核，不改原订单为已退。GET /api/refunds及/{id}按买卖双方/平台范围脱敏。
POST /api/refunds/{id}/review：系统管理员/运营批准或拒绝，expected_version/原因/经济方案；拒绝必填。POST /api/refunds/{id}/execute：批准后确认模拟执行，系统管理员/运营；财务403。普通与version_change源严格分开，版本降级仅Saga受控调用，不能由普通请求伪造source绕过审批。
状态requested→approved/rejected；approved→executing→completed/failed；失败只由受权人员重试，未明确取消已批准单不新增撤销捷径。终态不再审核/执行，渠道延迟回调不能把completed回退。锁原订单/经济段检查累计已退+在途批准金额不超限，禁止并发超退。
SaaS可退上限按有效未消费经济段成交收入*剩余秒/原完整秒，扣已批准/已退分配，分位Decimal统一ROUND_HALF_UP、尾差落最后分配。升降级已替代段不再冲回；未来续费分别计算，不以组合最新价替代历史实际价。
有限额度API已确认只按用量扣费：购买额度=月额度×购买月数；已消费金额=对应经济段实际收入×min(该段已用次数/购买额度,1)，可退金额=实际收入-已消费金额-已退分配，并扣除在途已批准退款占用；不加时间扣费。用量必须从持久化网关计量按企业共享组合拆到来源经济段，不能读取当前月计数代替历史总用量，不能在两个续费订单重复计同一次调用。版本切换分段计算，不能以当前版本覆盖旧段价格和额度。
不限额度API（月额度0）与SaaS按已用时长占比扣费，不除零、不按无限额度虚构次数。按原始有效经济段实际收入、完整秒数和未使用秒数计算，保留日历锚点，不使用固定30天。
部分退款具体映射已确认：有限额度API按退款金额/原成交金额比例扣减购买额度，不修改产品配置或影响其他订单；SaaS和不限额度API按同一比例扣减原时长，优先截短未使用尾部。分母与权益基数始终是原经济段，重复部分退款按累计已退金额计算累计回收，减去已回收值，避免重新以剩余金额作分母。额度整数及时间微秒累计向下取整，最后剩余可退金额全部退还时回收全部剩余未消费权益，不留下取整残余。不得回收已消费权益；退款上限与权益上限均校验。
多订单先将退款明确分配到来源经济段，各段分别计算，不影响无关续费；有限API维护独立累计退额预算，不重置订阅月已用量；时间退款缩短被退段尾部而非抹除原历史起止。执行步骤须消费冻结economic_plan。文件/线下审批必须提供人工核定及成本回冲依据；不默认退款比例等于所有成本比例。
## 9. Saga与月度清算
执行步骤：批准冻结经济方案→登记资金/资源执行任务→资源限制/回收→模拟资金确认→完成退款→负向经济分录+消息/审计。本地每步提交，外部调用不跨长事务。资源失败不得标资金已退；资金失败保持可恢复限制及状态，不自动恢复高权益。若真实资金先成功必须记录实况并转资源补偿，不能篡改成功资金事实。
同refund_id经济负分录唯一；transaction同时提交退款completed和本地负向分录/outbox，消息失败可重发但不重退。沿用create_refund_negative_settlement前先核对可覆盖的金额/成本范围，再扩展成依据allocation生成，保留旧完成单幂等。
收益及成本均有符号，五方分配依原规则快照；退款完成时间归属自然月，原月批次已支付不改，下一完成月份收负向。净降级退款已有经济双腿，不再通用重复冲回。清算总表、订单明细、产品及参与方报表包含负向，显示关联原ORD及REF，不混成普通购买单。
## 10. 通知审计
申请/审核通知买方及提供方当前super/admin去重；普通售后阶段通知责任人/双方，SLA超时通知责任方与监控。角色变更按发送时有效身份过滤，Outbox幂等且保留收件快照。站内+配置邮件失败独立，不回滚已批准交易。
审计记录ID、公开号、actor及角色、企业、from/to、金额变化、理由、request_id、结果；Secret/证件及买方不可见成本不写公开消息。系统拒绝动作也记录安全审计但不创建成功状态事件。
## 11. 开发顺序、测试与发布
阶段A：基线与历史盘点；阶段B：商城/权限/弹框/类型/分页/我的应用；阶段C：售后状态机及三方SLA；阶段D：普通退款/资源补偿/清算；阶段E：浏览器回归及发布。
API不限额度按时长、多月有限额度分母及部分退款缩减公式均已确认，移除退款公式确认门禁。历史类型迁移仍须盘点后用户批准。接口契约先定，前后端不重复发明状态。开发完成需单元、真实PG事务、权限负测、浏览器、market部署证据后review，用户验收done。
部署前备份，迁移先隔离恢复副本验证，按新镜像标签和版本标记发布；旧请求返回受控冲突而非绕过权限。回滚不得抹除已发生资金事件，采用前向修复/兼容读，禁止简单回退数据库删除事件。真实银行、供应商会话注销不具备条件单列。

## 12. SLA只读证据增量契约（2026-10-15）

- `GET /api/after-sales/{id}/sla/evidence`只读已持久化时钟，沿用工单双方企业管理员及平台授权角色的对象权限；支持责任方筛选和分页。返回测量时间、冻结目标/预警、规则及日历版本、事件依据和工单版本滞后提示。不调用旧物化时钟GET，不补造历史时钟；买方等待区间仅作观察，不冒充买方达标结论。
- `GET /api/sla/results/{id}/sources?metric=...&version=...`仅系统管理员/运营访问。评估事务新增`sla_assessment_evidence`版本记录，结论、冻结目标、as_of、闭合请求水位和安全来源快照同事务保存。旧版本查询不重连当前事实；无历史关联返回unknown，不倒推补写。评估/证据/审计/Outbox失败一并回滚，输入未变不重复生成版本。

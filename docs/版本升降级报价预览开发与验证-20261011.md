# 版本升降级报价预览：需求、设计与验收

## 一、范围与任务依赖

本批实现 TRD-BE-016，并完成 TRD-FE-009 的报价预览部分。适用 API、模型 API、SaaS 月度订阅；文件及线下服务不适用。

前置任务为 TRD-BE-010（持久化订阅期限）及 TRD-BE-013（SaaS 企业产品组合绑定）。TRD-BE-017 的资源变更及支付退款 Saga、TRD-BE-018 的清算冲回落账不在本批范围。报价成功或校验成功不代表版本已经切换。

## 二、功能要求

1. 已实名、有效的买方企业超级管理员及管理员可在本企业已支付、未退款且已交付的订阅订单详情中预览版本变更。普通成员、其它企业及平台角色不能代买方获取报价。
2. 当前及未来已付续费时段全部参加计算；未编排期限的已付订单、期限不连续、失效租户等情况阻止报价，不静默遗漏权益。
3. 原版本收入及成本使用每笔订单冻结的实际金额，不读取当前产品价格代替历史金额。
4. 目标版本月价及月成本乘原订单月数后，再乘该订单剩余秒数比例。未来未开始时段比例为 1；已经结束的时段不冲回。
5. 按每段原收入、原成本、目标收入及目标成本分别进行人民币分级 HALF_UP 舍入，再求净差额；费用计算使用 Decimal，不用浮点累计。
6. 示例：当前三个月订单原价 300 元、目标同期限价格 450 元，剩余一半产生差价 75 元；未来一个月原价 100 元、目标价 150 元，产生差价 50 元。总净应付 125 元。
7. 内部预览保留原版本剩余收入及成本的负向条目、目标版本剩余收入及成本的正向条目及各自清算规则快照。买方响应不包含成本、利润、清算规则、上游地址或 Secret。
8. 不兼容版本必须先确认兼容性提示。报价最多有效五分钟，且不超过当前时段结束时间；原订单、未来时段、目标配置及规则变更使原报价失效。

## 三、接口与数据设计

| 接口 | 用途 |
| --- | --- |
| GET /api/orders/{id}/version-change-options | 获取有效目标版本、兼容性说明、订阅到期及服务器时间 |
| POST /api/orders/{id}/version-change-quote | 提交目标版本与兼容性确认，返回逐段报价及签名凭据 |
| POST /api/orders/{id}/version-change-quote/validate | 校验签名、用户订单绑定、有效期及业务快照是否变化 |

新模块 `backend/app/version_change_quotes.py` 复用现有订单经济快照、交易权限、日历期限及企业组合锁，不新增数据库表。本批为只读操作，不创建订单、支付、退款、清算或网关资源。

报价 JWT 使用独立 audience 和 purpose，与登录令牌区分。业务快照指纹使用带密钥的 HMAC，避免通过公开指纹猜测隐藏成本；令牌不携带成本及资源密钥。报价接口禁止缓存。后续执行任务必须在自身业务锁下重新校验，不能仅相信前端已校验标识。

公开金额字段：原订单整段金额、原版本剩余金额、目标版本同期限整段金额、目标剩余金额及段净差额。总计展示净应付、净应退或零差价。`execution_ready` 固定为 false。

## 四、前端设计

订单详情订阅区域提供“版本变更”入口。同风格弹框包括目标版本、不兼容确认、逐段金额和剩余比例、总差额、报价到期、获取报价、校验、刷新及关闭。无执行变更、支付或退款按钮。

签名令牌保留在会话闭包，不进入可渲染状态。切换用户、企业、订单、目标版本或兼容性确认会清理旧报价，并丢弃陈旧异步响应。依据后端服务器时间加客户端经过时长判断到期，兼容浏览器与服务器时钟偏差。

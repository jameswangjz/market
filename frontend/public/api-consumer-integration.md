# API 应用调用方接入与调用规范

版本：v1.1（订阅续费与配额阶段，2026-10-10）

本文件面向购买或准备购买 API 服务、模型 API 的用户和企业应用开发人员。用户可以在购买前查阅本文件，了解接入方式、凭据管理、调用地址、配额和错误处理规则。

## 1. 接入方式

平台采用“统一 API 网关集群 + API 服务独立部署”架构。调用方不直接访问 API 提供方，而是访问平台统一网关：

```text
调用方应用 -> 统一 API 网关 -> API 提供方业务服务
```

开发环境网关地址：`http://192.168.10.10:30082`。生产环境使用平台提供的 HTTPS 域名；`30081` 仅用于旧网关回退验证。

产品详情或订单中会提供以下信息：

- 网关地址；
- `route_key`；
- API 版本和路径；
- 调用方式和请求参数；
- 当前产品的配额和超时时间。

## 2. 购买前确认

购买前应确认：

1. API 产品的版本、价格和授权范围；
2. 是否支持文件、JSON 或流式响应；
3. 每分钟、每日和每月调用配额；
4. API 版本和兼容期；
5. 是否需要企业身份、数据权限或国密算法支持；
6. 业务接口的请求参数、响应字段和错误码。

API、模型 API 的版本价格和成本按月定义，订单按购买月数计算，支持 1～36 个月。每个版本有独立说明、每分钟限流、每日限额和订阅月配额；登记时月配额以千次输入，平台按实际调用次数保存，0 表示不限额。

新订阅采用“企业 + 产品”共享调用凭据及用量。同版本续费只延长服务截止时间，不叠加当前限流和配额，也不提前重置当前用量。服务期限从实际交付成功开始；按原始生效日计算订阅月，目标月份无对应日期时取月末，后续月份仍使用原始日期。每日限额按北京时间自然日重置。未来已购买时段在开始前不增加当前权益；每笔订单保留独立时段及财务快照。

当前阶段已实现同版本续费；跨版本升降级尚未开放。不同版本不能通过再次普通购买绕过版本变更流程。旧计数模式的历史凭据保留原行为，有历史用量时不得直接切换或清零，须完成专门的迁移校验。

API 提供方的服务可以部署在独立 Kubernetes 集群、虚拟机、物理服务器或云主机中，调用方不需要关心其部署位置。

## 3. 凭据获取和生命周期

订单支付且实际交付成功后，可进入订单详情页的“API 调用凭据”区域。新订阅按“企业 + 产品”共享身份、按审核通过的版本路由授权：

- 已实名且属于已认证购买企业的企业超级管理员、管理员可以管理调用凭据；
- 普通企业成员不可获取文件或 API 凭据；平台管理角色不因此获得买方 Secret；
- 公开商城允许匿名浏览，订阅须选择符合权限的企业；买方发起支付仅限企业超级管理员，平台财务保留人工到账确认。

首次获取凭据时，平台生成 API Key 并只在本次操作结果中显示原文。同一企业后续订单会复用已有 API Key，不会重复生成；调用方必须立即保存，不要把 API Key 写入前端代码、镜像或公开代码仓库。

订单页面支持停用和重新生成企业共享凭据。重新生成会立即停用旧凭据，但不重置企业产品组合的已用次数。同版本续费不会自动恢复手工停用的凭据。未交付、未开始或已到期的时段不能用于当前调用；所有有效权益结束后网关拒绝访问。跨版本切换及其退款、冲回清算仍属于后续开发内容，不能将旧版额度退款算法视为新订阅完整处理能力。

订单页面接口如下：

```http
GET  /api/orders/{order_id}/api-credentials
POST /api/orders/{order_id}/api-credentials
POST /api/orders/{order_id}/api-credentials/{credential_id}/revoke
POST /api/orders/{order_id}/api-credentials/{credential_id}/regenerate
```

以上为平台登录后的管理接口，实际使用时优先通过订单详情页面操作。

## 4. 网关调用

调用地址格式：

```text
{gateway_base_url}/gateway/{route_key}/{api_path}
```

使用 `X-API-Key`：

```http
GET /gateway/quality-api/v1/quality-score?equipment_id=EQ-001 HTTP/1.1
Host: gateway.example.com
X-API-Key: mk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
X-Request-Id: req-20261006-0001
Accept: application/json
```

也可以使用 Bearer：

```http
Authorization: Bearer mk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

平台网关不会把认证头转发给第三方 API。认证成功后，网关会向 API 提供方注入：

```http
X-Market-Enterprise-Id: <调用企业ID>
X-Market-Route-Key: <网关路由标识>
```

调用方不得伪造或依赖直接传递企业身份，企业身份以平台网关鉴权结果为准。

## 5. 请求和响应

支持 `GET`、`POST`、`PUT`、`PATCH`、`DELETE`、`HEAD` 和 `OPTIONS`。业务参数按照 API 提供方的接口说明放在路径、查询参数或 JSON 请求体中。

推荐响应格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "req-20261006-0001"
}
```

写操作必须携带 `X-Request-Id`，建议同时携带 `Idempotency-Key`。调用方重试时应使用相同幂等号，避免重复创建、扣费或变更。

文件接口应保留响应中的 `Content-Type`、`Content-Disposition` 和文件名。大响应建议使用分页、压缩或异步任务。

SSE 或其他流式接口调用时增加：

```http
X-Market-Stream: true
```

或设置：

```http
Accept: text/event-stream
```

## 6. 限流和配额

平台支持：

- 每分钟调用频率限制；
- 每日调用配额；
- 按原始生效日划分的每订阅月调用配额，每日按北京时间自然日统计；
- 企业与产品组合共享计数，不按订单或 API Key 数量放大额度；
- 同版本多订单只顺延期限，当前配额不叠加；新的时段尚未开始时不提前增加或重置额度；
- 配额超限返回 HTTP 429。

调用方不应通过并发放大绕过配额。收到 429 时应读取 `Retry-After`（如有），或采用指数退避。

## 7. 错误和重试

```json
{
  "code": "QUOTA_EXCEEDED",
  "message": "超过 API 每日调用配额",
  "request_id": "req-001",
  "retryable": false
}
```

| 状态码 | 说明 | 建议 |
|---|---|---|
| 401 | 凭据缺失、错误、过期或停用 | 不重试，检查凭据 |
| 403 | 订单授权或业务权限不足 | 不重试，检查产品授权 |
| 404 | 路由或资源不存在 | 不重试，检查版本和路径 |
| 409 | 幂等或业务状态冲突 | 使用相同幂等号查询结果 |
| 429 | 超过限流或配额 | 退避后重试 |
| 502 | API 提供方不可用 | 幂等请求最多重试 3 次 |
| 504 | API 提供方超时 | 幂等请求最多重试 3 次 |
| 5xx | 服务端错误 | 仅对幂等请求重试 |

平台网关当前不自动重试业务请求。调用方应自行控制重试次数和退避时间，非幂等请求必须先查询上一次请求结果。

## 8. 版本和变更

- API 版本通常通过 `/v1`、`/v2` 等路径区分；
- 新版本不代表旧版本订单自动获得访问权限；
- 发生不兼容变更时，API 提供方应发布迁移说明和兼容期；
- 调用方应避免硬编码不可变更的后端地址，只使用平台提供的网关地址和路由；
- 企业产品组合已无有效授权时，原凭据不能继续调用；单个续费段尚未开始也不能提前用于调用。
- 跨版本升降级尚未开放，完成资源变更和财务补偿验证后才会提供该功能。

## 9. 联调示例

```bash
curl -X GET \
  'http://192.168.10.10:30082/gateway/quality-api/v1/quality-score?equipment_id=EQ-001' \
  -H 'X-API-Key: <企业共享 API Key（订单页面生成）>' \
  -H 'X-Request-Id: test-001' \
  -H 'Accept: application/json'
```

验收时应验证：正常调用、错误凭据、停用凭据、过期凭据、订单授权失效、超过限流、超过每日/月度配额、文件下载、流式响应、502 和 504。
